# 财报速览修订执行（审计之后的第二阶段）

审计（见 `财报速览内容审计.md`）给出意见后，用户通常会**限定范围**要求改稿，例如：

> "只先修 A 组四处硬错 + 补前 5 项遗漏。"

本文件是这一阶段的执行手册。改稿比审计更容易出错——审计错只是意见不准，改稿错是把新错误写进成品。

## 0. 动手前：把范围写成清单

用户说"A 组四处 + 前 5 项"时，先在回复里（或心里）把**具体是哪 4 处、哪 5 项逐条列出来**，编号 A①–A④、遗漏 1–5。
之后每次 `patch` 前问一句：这一处属于清单里的哪一条？答不上来就是越界。

**越界是最常见的失败模式。** 实测两次踩坑：

1. 想补全"现金流压力"叙事，顺手加了"分红时点错配"一段——那是遗漏清单的**第 6 项**，不在"前 5 项"内。写完才发现，整段删除。
2. 改黄灯时顺手写入"存货增量 75% 是库存商品而非原材料"——这是 **B 类口径发现**，不属于 A 组硬错。更糟的是：正文存货条仍写"可能与原材料备货有关"（不在范围内、未改），于是**黄灯与正文直接打架**，制造了一处新的自相矛盾。

**规则：范围外的发现，哪怕是对的、哪怕就在手边，也只能在最后向用户口头报告"还发现 X，要不要一起改"，不能写进稿子。**

## 1. 写入前必须回源复验审计结论（最重要）

审计阶段的数字常常来自**部分提取 + 心算**，其中会混入口误。改稿时若直接粘贴，等于"修旧错的同时引入新错"。

实测：改稿前重新对 PDF 原文取证，发现自己审计报告里三处不准——

| 审计时写的 | 财报原文 | 后果 |
|---|---|---|
| PB 处于 **75%** 分位 | 实算 **59%**（3.85 / 2105 日） | 估值反差结论的量级被夸大 |
| **8 家**子公司高新资质到期 | **9 家** | 漏列一家 |
| 沈阳汽车玻璃 **11/6** 到期 | 沈阳是 **11/29**；11/6 是天津和苏州 | 张冠李戴 |

**规则：凡是要写进文章的数字、日期、家数，一律重新跑一遍计算或重新 grep 一遍原文，不用审计阶段的记忆值。**
分位、倍数、同比这类派生数尤其要用 `execute_code` 实算并打印，不要口算。

## 2. 级联修改：一处硬错往往散落在 4–8 个位置

财务速览的结构（标题注 → 速览表 → 表注 → 正文四节 → 红绿灯 → 估值节 → 观察点）会让同一个数字重复出现。
**只改正文会留下自相矛盾的成品。** 每修一处硬错，立刻列出它的全部落点。

福耀 A① 行情取错日期（57.06 元 / 1489.12 亿 / PE 17.56）实际牵连 **9 处**：

- 标题下引言"按 9 月 2 日收盘实测"（可信度标签）
- 速览表 PE 行数值与分位（23% → 21%）
- 表注里的"市值、PE 按 9 月 2 日收盘实测"
- 估值节 PE-TTM 口径推导（分子市值）
- 2026E 外推的对应 PE（18.6 → 18.4 倍）
- 第四节股息率的现价基准（57.06 → 56.37，3.5% → 3.55%）
- 归一化段"股价涨 2.98 倍"（→ 2.94 倍）
- "股价从 2021 年高点回落"（实为 2025-09 高点 74.20 元）
- "市值也从高点腰斩过"（实为回撤 24%，非腰斩）

同理 A③ 归因方向错牵连：正文 Q2 段 + 黄灯第二条；A④ 口径错牵连：表行 + 表注 + 正文 + 绿灯一条。

## 3. 改完用一次 grep 清残留

把所有旧值拼成一个正则，全文搜一遍，确认无残留：

```bash
# search_files target=content，path 指向文章
57\.06|1489\.12|17\.56|17\.6 倍|腰斩|净现金约 3\.7|拖累其实更小|主业走弱|18\.6 倍|两成低分位
```

要点：
- **不只搜数字，还要搜措辞**（"腰斩""主业走弱""拖累更小"）——数字改了但旧结论的形容词还在，是常见的半截修改。
- 命中后逐条判断：是残留错误，还是**新写的正文里正当引用了旧表述**（如"措辞上不宜说成'主业走弱'"）。后者保留。

## 4. 改完必须整篇重读一次

`read_file` 通读全文（不要用 offset 片段读），专门查三类不一致：

1. **计数一致性**：黄灯写"五项"实际列了 4 条？绿灯写"八项"实际 8 条？改灯时要重新数。
2. **新旧正文互斥**：改了黄灯但没改对应的正文条（见第 0 节踩坑 2）。
3. **同一事实两个数**：本次实测——归一化段写"回撤约 23%"，估值段写"回撤约 24%"。
   23% 是用 9/3 收盘价 57.01 算的旧值，24% 才是 9/2 的 56.37/74.20。统一成一个。

## 5. 替换绿灯时的取舍要报备

为保持"绿灯八项"，用新补的指标（加权 ROE）替换掉一盏重复计数的灯（高附加值产品渗透 +8pct，与"毛利率创新高"同一因果链）。
这类**为了守恒而做的替换，必须在交付说明里明确告知用户并给出换回选项**——用户可能更想保留原来那盏、让绿灯变九项。

## 6. 上游数据源缺陷：报告但不擅自修

行情错值的病根在 `charts/{code}_季度数据.csv` 最后一行（`close` 与 `trade_date` 不匹配），
而归一化 PNG 是用那一行画的。改完文章后会出现**图文微小出入**（正文 2.94 倍 vs 图里 2.98 倍）。

正确做法：**改文章（在范围内），然后把数据源缺陷和图文不一致单独报告给用户，问是否要顺手修 CSV 并重绘图。**
不要因为"图文明显不一致"就自作主张改 CSV、重跑图——那是另一个范围的工作，且会改动用户的既有产物。

## 7. 交付说明的格式

改完给一张紧凑的对照表，让用户能逐条验收：

- A 组：`| # | 旧 | 新 |` 四行，每行写清改了什么、连带改了哪些落点
- 遗漏：编号列表，每条写"补在哪一节 + 关键数字"
- **两处需交代**：自己审计口误的更正（诚实列出）、为守恒做的替换（给换回选项）
- 末尾：范围外但建议处理的事项（数据源缺陷、B 类口径问题），等用户点头

## 8. PDF 取证的可复用手法

`search_files` 对中文关键词搜 PDF 常返回 0 命中（抽取层与搜索索引不匹配）。可靠的办法是**先落盘成 txt，再用 Python 正则带上下文窗口**：

```python
from hermes_tools import terminal
terminal('''python3 -c "
import fitz
d=fitz.open('报告.pdf'); t=''.join(p.get_text() for p in d)
open('/tmp/x.txt','w').write(t); print(len(t))"''', timeout=180)
```

然后 `re.finditer` + 前后各取 200–900 字符打印。

**PDF 表格抽取会串列**，"实体名—数值"配对会错位。取清单类信息（如各家子公司资质到期日）用**锚点回溯法**：
先匹配确定性的值，再向前回溯固定字符数找实体名标记——

```python
for m in re.finditer(r'资格将于(202\d\s*年\s*\d{1,2}\s*月\s*\d{1,2}\s*日)到期', t):
    pre = t[max(0, m.start()-420):m.start()]
    i = pre.rfind('注册于')          # 该值前最近的实体名标记
    name = pre[:i].strip()[-24:]     # 取标记前的主体名
```

这样能一次性抓全 9 家，避免逐家人工翻找漏项。抓到后仍要**打印全部命中数**核对家数，不要凭"看起来抓完了"。
