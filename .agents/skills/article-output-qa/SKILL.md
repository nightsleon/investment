# 投资文章 QA：机械校验 + 内容审计

## When to Use

投资类文章发布前或发布后的质量检查，两类任务：

**（一）机械 QA**（本节 1–3）——markdown 长文（指数对比、基金对比等）的表格渲染、图表口径、图注规则。

**（二）内容审计**（见 `references/财报速览内容审计.md`）——用户要求"根据财报校验这篇文章：
1.数据严谨性 2.表达是否通俗简练 3.有没有投资者应该关注却遗漏的点"。这是对已有文章做复核并出审计意见，
不是重写。触发词：校验/复核/审计/挑错/看看有没有问题。

**（三）修订执行**（见 `references/财报速览修订执行.md`）——审计出意见后，用户限定范围要求改稿，
如"只先修 A 组四处硬错 + 补前 5 项遗漏"。**改稿比审计更容易出错**，必须走那份手册：
范围清单化 → 回源复验审计数字 → 逐处硬错列出级联落点 → grep 清残留 → 整篇重读查不一致。
触发词：修/改稿/只改 X/补上前 N 项。

分析与写作本身由 `stock-financial-speedread`、`dividend-index-analysis`、`index-performance-backtest`、
`stock-investment-article` 等 skill 负责；本 skill 只做质量把关。

## 内容审计速览（详见 references/财报速览内容审计.md）

三维审计的要点，动手前先读那份 reference（含完整检索清单与实测案例）：

1. **凑齐原始依据**：本期报告 PDF 全文 + 上一期季报 + 上年年报 + 日频 `pe_history.csv` + 季度 CSV。缺任何一个都会漏判——
   没有一季报就无法验单季归因方向，没有日频行情就无法验"实测"标签。
2. **数据严谨性分三类**：A 硬错（分项加总不符、行情取错日期、归因方向反了、历史极值判错、口径错标）；
   B 口径不严谨（税前/税后混叙、整体/分部口径、"新高"无区间、跨维度类比当披露、一次性损益只报支出）；
   C 核对正确（也要列出来，让作者知道覆盖面与问题集中度）。
3. **表达**查六项：重复、注释过载、术语无解释（尤其两个同名概念，如中国准则资产负债率 vs IFRS 资本负债比率）、
   数字格式不统一、调性割裂、红绿灯重复计数（同一因果链只算一盏灯）。
4. **遗漏点**是审计最有价值的部分——作者漏的往往不是数字，而是**没去读那几个章节**：税项附注（退税率变动、
   高新资质到期日、海外子公司亏损）、在建工程项目预算表（转固折旧压力）、存货分类别、主要财务指标表（ROE/EBITDA比）、
   `pe_history.csv` 的 PB 列（与 PE 分位对照）、未确认递延所得税资产的可抵扣亏损、筹资活动现金流分解、债券章节、
   股东情况章节、主要子公司表、关联交易表、员工人数。
   **排序原则：把"有日期、可量化、已生效"的确定事项排在宏观展望之前**——作者常把篇幅给后者，但前者信息量更大。
   **"第二增长曲线"类叙事必须给反面证据**，否则说服力打折。
5. **输出**：三段式对齐用户的三问，末尾给总体判断（框架是否成立、核对了多少项、必须处理才能发的是哪几类、
   最大内容缺口），最后主动问是否要出修订稿（全量 or 只修硬错+补重点遗漏）。

## 机械 QA

### 1. Markdown 表格列数一致性（渲染检查）

每张表的**表头、分隔行、每一行数据**的单元格数必须相等。分隔行多一格或少一格都会导致整表无法渲染（常见症状：多了一个 `---` 使分隔行 11 格而表头 10 列）。

校验：直接运行

```bash
python3 scripts/check_markdown_tables.py 文章.md
```

脚本逐表比较所有行列数并报告异常。注意脚本按 `|` 切分，含转义竖线 `\|` 的单元格会误计数，遇此类表格人工复核。

### 2. 图表截止日与文章口径对齐

图内所有序列的截止日必须与文章表格/正文完全一致。常见坑：新增基准序列（如沪深300全收益 H00300）的归档数据只到较早日期（如 07-31），而文章窗口到 08-07——此时图里同一指数的年化与表格年化打架。

实测量级：截止差 5 个交易日，年化可差约 0.4 个百分点（红利低波全收益 2016-08-08 起算：2026-07-31 口径 9.28%，2026-08-07 口径 8.86%）。文章本身也强调"截止日差几天数字会有出入"，正文数字之间更不允许自相矛盾。

做法：出图前先核对每个序列的末端日期，基准序列归档不足时**先补采到统一截止日再出图**（中证官网接口现成，小步骤），保证图、正文、表格三个数字完全一致。

## 3. 图注规则与结论摆放

- 图下**不写小结段落**：走势结论（含关键数字）写进支撑章节正文，数字必须实算引用；
- 图内标签只标注简称 + 区间收益，标题保持中性；
- 结论进正文的骨架：先理论背书再摆数据；论证"慢指数赢大盘"这类观点时，三个支撑点各配实据——赢（年化/累计对比）、稳（亏损年数、最大回撤、熊市对照年份）、实盘（指数发布日期早于窗口、无回测成分）；反例年份也要如实写（如核心资产牛市大盘反超）。

## Verification Checklist

**内容审计（用户要求"根据财报校验"时）**
- [ ] 原始依据齐备：本期报告 PDF 全文 + 上一期季报 + 上年年报 + 日频 `pe_history.csv` + 季度 CSV
- [ ] 所有括号内分项枚举已重新加总核对声称总额
- [ ] 现价/市值/PE 已回日频 CSV 按文章声称的日期取值，季度 CSV 的 close 未被当权威源
- [ ] 单季归因已按**同比摆动额**（带上期符号）验证方向，且给出了"扣除该因素后同比"的正负与量级
- [ ] "创新高/历史高点/腰斩/回撤"类表述已用日频序列算 max/min 核对
- [ ] 税前 vs 税后、整体 vs 分部、货币资金 vs 现金及等价物、摆动额 vs 单期额——四组口径未混叙
- [ ] 已检索税项附注（退税率/优惠资质到期/海外子公司亏损）、在建工程预算表、存货分类别、
      未确认递延所得税可抵扣亏损、筹资活动现金流分解、股东户数与机构增减仓、关联交易占同类比例
- [ ] 遗漏点已按"有日期可量化的确定事项 > 宏观展望"排序，"第二增长曲线"叙事已给反面证据
- [ ] 表达六项已查（重复/注释过载/术语无解释/数字格式/调性/红绿灯重复计数）
- [ ] 输出为三段式对齐用户三问，末尾有总体判断 + 主动询问是否出修订稿

**修订执行（用户限定范围改稿时，详见 references/财报速览修订执行.md）**
- [ ] 已把范围写成编号清单（A①–A④ / 遗漏 1–5），每次 patch 前确认属于哪一条
- [ ] **审计阶段的数字已回源复验**（分位实算、家数 grep 全量、日期逐个对原文）——审计口误会被改稿写进成品
- [ ] 每处硬错已列出全部级联落点（引言/速览表/表注/正文/红绿灯/估值节/观察点），一处不漏
- [ ] 范围外的发现只在交付说明里口头报告，未写进稿子（越界会制造黄灯与正文打架的新矛盾）
- [ ] 已用正则搜旧值 + 旧措辞清残留（"腰斩""主业走弱""拖累更小"这类形容词也要搜）
- [ ] 已整篇重读：红绿灯计数、新旧正文互斥、同一事实是否出现两个数
- [ ] 为守恒替换掉的绿灯已向用户报备并给换回选项
- [ ] 上游 CSV/PNG 缺陷已报告但未擅自修改（等用户点头）

**机械 QA（发布前）**
- [ ] 逐表校验：表头/分隔行/数据行列数一致（脚本）
- [ ] 图内序列截止日与正文/表格统一，基准序列不足时已补采
- [ ] 图下无小结段落，结论在正文且数字实算
- [ ] "赢、稳、实盘"三支撑点各有实据，反例年份未隐藏
