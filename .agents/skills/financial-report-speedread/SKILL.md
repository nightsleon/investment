# 财报速览（季报/中报/年报快速分析文章）

## 触发条件（高优先级）

当用户提到以下任意组合时，**立即加载本 skill**，不要先做 web search 或自行拼凑分析：

- 公司名 + "财报"/"中报"/"年报"/"季报"/"半年报"/"业绩"
- 公司名 + "分析"/"速览"/"解读"/"点评"
- 股票代码 + 上述关键词
- "XX公司最新财报" / "XX公司2026中报"

**反模式**：用户说"分析农夫山泉中报"，模型先去 web_search 搜新闻，自己拼凑数据输出 → 错误。应先 `skill_view(financial-report-speedread)` 加载本 skill，再按流程执行。

## 最新报告期优先

当用户说"中报"、"年报"、"季报"时，**默认指最新一期**。如果用户未指定年份，按当前日期推断最近的报告期，不要分析过期的旧报告。

## 定位与边界

单家公司的季报/中报/年报发布后，产出给普通投资者看的"财报速览"文章。

- 速览 = **标准 6 个论证位，弹性上限 10 个**（一个论证位 = 数字 + 一步推导 + 结论）。
- 超 6 个时先精简：合并同类论证、数字移进表格（表格不计论证位）。精简不了可放到 10 个，但超过 10 个说明本期财报过于复杂，应提示用户"建议拆分议题单独讨论"。
- 本 skill 始终只产速览，不升级为其他体裁。
- 仅支持 **A 股** 和 **港股**，不支持美股。

方法论详细定义见用户仓库 `references/财报速读指南.md`。四问框架要点摘要见 `references/四问框架要点.md`。实战翻车案例见 `references/实战案例.md`。

## 流程（6 步，顺序固定）

### 步骤 1：路由判断 + 下载 PDF

**1a. 路由判断**——确定公司类型，加载对应 checklist：

| 维度 | 判断方法 | 影响 |
|---|---|---|
| **上市地** | A 股（沪深代码）还是港股（5位数字） | 数据源、会计口径、PE 接口 |
| **涉外程度** | 海外收入占比是否显著（>20%） | 是否触发汇兑类 pitfall |
| **行业** | 制造 / 消费 / 金融 / 其他 | 核心跟踪指标、排雷重点 |

路由结果：
- A 股 → 加载 `references/checklists/a_stock.md`
- 港股 → 加载 `references/checklists/hk_stock.md`
- 涉外企业 → 追加 `references/pitfalls/conditional.md` 中的汇兑板块
- 制造业 → 追加存货/在建工程/资本开支板块

**1b. 下载财报 PDF**——数据唯一准绳：

- **A 股**：巨潮资讯网公告列表 `https://www.cninfo.com.cn/new/hisAnnouncement/query`（POST，带 `plate=sz|sh` + `stock=代码`）；东财兜底：`https://np-anotice-stock.eastmoney.com/api/security/ann?sr=-1&page_size=50&ann_type=A&client_source=web&stock_list=代码`，拿 `art_code` 拼 PDF。
- **港股**：港交所披露易 `https://www1.hkexnews.hk/search/titlesearch.xhtml`（搜公司名/股票代码），或公司官网 IR 页。

**港股 PDF 发现陷阱**：HKEXnews 的 URL 模式不规律（如 `2026/0825/2026082500511_c.pdf`），不能猜测。必须按以下优先级尝试：

**利润数据口径一致性**：计算 TTM 时，所有历史利润数据必须来自已公布的财报（年报/中报），不得使用未公布或推算的未来数据。常见错误：
- 误将 FY2025 全年数据（尚未公布）加入 TTM 计算，导致数据失真
- 混淆 H1 累计值与单季度值，港股只有半年报和年报，没有季报
- 基期利润 TTM 为负时，归一化图会出现负值假象，应改用第一个正 TTM 点作为基期

**港股 PE 获取与量化对齐规范**：
1. **实时行情与估值首选**：直接运行内置脚本 `python3 scripts/fetch_valuation.py {代码}`，自动完成东财/腾讯官方接口调用、实时港币/人民币汇率折算并输出官方 `f164` PE(TTM) 与 PB。
2. **历史序列回算铁律（杜绝与同花顺/Wind产生分位偏差）**：
   - **PIT 披露日生效**：构建利润阶梯时，跳变生效日必须是**业绩公告实际发布日（`announcement_date`）**，严禁以 6/30 或 12/31 期末日提前切换（杜绝前视偏差）。
   - **逐日动态汇率**：每日市值换算必须匹配当日外汇中间价（如 yfinance `HKDCNY=X`），严禁全历史套用固定估算汇率（如 0.90）。
   - **分位数窗口明确**：明确标注统计窗口与样本分母（如“同花顺近5年 0.81% 分位 / 上市以来 X% 分位”）。
3. 存 `data/pe_history.csv`，日频。

**PDF 来源优先级链（按顺序尝试，前一个失败再试下一个）**：
1. **公司官网 IR 页 / CDN**（最可靠）：很多港股公司在官网设有 IR/财务信息页面，PDF 托管在公司自有 CDN 上。例如农夫山泉的 PDF 托管在 `file-cloud.yst.com.cn`。用 `web_search` 搜索 `{公司名} 官网 财务信息` 或 `{公司名} IR page`，找到公告列表页，直接取 PDF 链接。
2. **新闻镜像站**：moomoo（`newsfile.moomoo.com`）、富途等券商平台会镜像托管公告 PDF。搜索 `{公司名} {年份} 中期业绩 site:moomoo.com` 或 `site:futunn.com`。注意：moomoo 的 PDF 通常是完整版（30+ 页），可直接用 `web_extract` 提取文本（有时比下载 PDF 更快）。
3. **港交所披露易搜索**：访问 `https://www1.hkexnews.hk/search/titlesearch.xhtml`，用股票代码搜索，从结果列表中获取 PDF URL。
4. **`_c` 后缀规则**：港股公告 PDF 的 URL 通常带 `_c` 后缀（中文版）。如果搜索到的是不带 `_c` 的 URL（如 `2025082600883.pdf`），**立即追加 `_c`**（变为 `2025082600883_c.pdf`）。无后缀的 URL 经常返回 404 HTML 页面而非 PDF。
5. **巨潮资讯网（A 股 + 部分港股）**：`https://static.cninfo.com.cn/finalpage/...` 格式的 URL。但**注意反爬**：cninfo 的 CDN 有 WAF 防护，裸 curl 会被 403。需要带完整浏览器 headers（Referer、Accept-Language、Cookie）。如果直接下载失败，用 `web_extract` 提取。

**下载后立即验证**（不可跳过）：用 `file` 命令或 `python3 -c "import fitz; ..."` 检查：
   - 文件确实是 PDF（检查前 4 字节是否为 `%PDF`）
   - 公司名称匹配（如"农夫山泉股份有限公司"）
   - 股票代码匹配（如"9633"）
   - 报告期匹配（如"截至2026年6月30日止六个月"）
   - 如果文件是 HTML（404 页面）或内容是其他公司（如 CBBC 产品、牛熊证公告），删除并尝试下一个来源。

**常见下载陷阱**：
- 搜到的第一个 hkexnews PDF 链接可能是衍生产品公告（如 J.P. Morgan 的 CBBC 牛熊证），不是公司业绩公告。必须验证内容。
- 不带 `_c` 的 hkexnews URL 几乎总是返回 404 HTML 页面，看起来像 2KB 的 PDF 但实际是错误页面。
- cninfo.com.cn 的 `finalpage` URL 经常被 WAF 拦截返回 403 HTML 页面。

**扫描版 PDF 提取**（`read_file` 失败时的强制回退链）：

港股公告 PDF 经常是扫描版（无可提取文本层）。当 `read_file` 报错 `"PDF has no extractable text"` 或 `"OCR is required"` 时，**立即切换到 pymupdf**，不要重试 `read_file`：
```bash
python3 -c "
import fitz
doc = fitz.open('path/to/report.pdf')
for i, page in enumerate(doc):
    print(f'--- Page {i+1} ---')
    print(page.get_text())
"
```
如果 pymupdf `get_text()` 也返回空字符串（纯扫描件，无文本层），则需要 OCR：
- 优先 marker-pdf（`marker_single path/to.pdf`）
- 备选 tesseract + pdf2image

**反模式**：反复用 `read_file` 尝试同一个扫描版 PDF → 浪费时间且会触发 tool loop warning。第一次失败就切 pymupdf。

- 区分**摘要 PDF 与全文 PDF**：摘要只有主要会计数据，四问分析必须全文。
- 文件命名：`{公司}：{期数}报告.pdf`，存入 `年报/` 子目录。

### 步骤 2：提取数据 + 校验

用 `read_file` 读 PDF（带行号文本），逐项提取：营业收入/成本、归母/扣非净利润（A 股）、税金及附加、三费、研发投入、经营现金流净额、销售收现、货币资金（+定存翻附注）、存货、应收、合同负债、有息负债（短借+长借+应付债券+一年内到期）、商誉、在建工程、总资产/总负债。

**港股差异**：IFRS 无"扣非净利润"概念，关注公司自行披露的 adjusted/underlying profit；关注分部报告（segment report）的分部利润。

**⚠️ 港股公告类型差异（致命陷阱）**：港股有两类中期披露文件，披露内容差异巨大：
- **中期业绩公告（Preliminary/Interim Results Announcement）**：通常只含利润表、全面收益表、资产负债表和附注，**不含现金流量表和权益变动表**。这是8月底最先发布的文件。
- **中期报告全文（Interim Report）**：9月下旬发布，包含完整四表（含现金流量表和权益变动表）。

**提取时必须先验证该报表是否真的存在于PDF中**：搜索"現金流量表"或"Statement of Cash Flows"，确认该表确实在PDF页码范围内。**如果不存在，该节必须写"该公告未披露现金流量表，完整数据待中期报告全文发布后补充"，绝不可编造任何现金流数字。** 这是最严重的数据完整性违规（幻觉数据），比缺数据更危险。

**资产负债表基准数必须从年报PDF原文逐项核实**：当期报告中的"上年同期"列可能与上年年报终值有差异（如分红计提冲减了未分配利润）。核实方法：打开上一期年报PDF提取文本，grep"权益总额"和"计息借贷"确认原始数字。不可从记忆中引用或推算基准数。

**校验（执行代码复算，不可跳过）**：
- 所有比率、同比用 PDF 原始值复算，不抄新闻
- 毛利率、净利率、收现比（销售收现/营收）、现金流/净利润
- 单季 = H1 − Q1（Q1 需一季报 PDF）
- **存货/应收周转天数官方披露优先**：必须先检索 PDF 中管理层讨论与分析（MD&A）原文。港股中报通常已直接披露标准天数（如农夫山泉 P22 披露存货 94.7 天、应收 4.5 天），严禁未查原文便自行盲目套公式估算导致与官方公告矛盾；若确无披露，半年报必须按 180 天或做年化基准严格换算。
- 净利增速偏离营收增速时，按指南第一问「利润三步拆解」归因

**逻辑归因反向验证**：对每个"由 X 导致 Y"的归因判断，用数据交叉验证。详见 `references/pitfalls/conditional.md`。

### 步骤 3：出图（独立前置步骤，排在写文章之前）

**图是文章的依赖件，不是可选附件。** 漏图是速览最高频事故。出图完成后才开始写文章。每篇财报速览**标配两张图**：

#### 1. 核心业绩看板 / 封面图（Executive Dashboard Card）
- **定位**：全篇视觉首图与封面。读者无需翻看长文报表，3 秒钟看清最核心的“大盘增速、业务分化与安全底牌”。
- **插入位置**：正文「## 一句话结论」正下方、「## 主要指标速览」正上方。亦作为社交平台（雪球/知乎/微信公众号）文章封面首图。
- **规格比例**：16:9 横版（如 1200×675 或 1600×900），白底/微灰底加品牌主题色点缀。
- **三层架构设计**：
  1. **顶部通栏**：品牌标识/Logo + 报告期标题 + 核心大盘指标（营收与同比、归母/经调整净利与同比）。
  2. **中段业务对比（核心看点）**：左右双栏对比展示主营分化。
     - 亮点/增长引擎（绿色高光）：销量/交付突破、核心产品放量、战略催化；
     - 承压/痛点板块（橙黄警示）：毛利率探底/受压、原材料暴涨、行业价格战，同时配上 ASP/高端化等对冲亮点。
  3. **底部基底**：
     - 家底安全垫：现金储备（或净现金）、存货健康度、年内分红/回购；
     - 估值锚点：现价、PE-TTM 与历史分位数。
- **生成方式**：调用 `generate_image`（AI 生成企业科技风高清信息图海报）或 Python 代码渲染；图存 `charts/{公司}_{期数}_核心业绩看板.png`。

#### 2. “股价 vs 利润 TTM”归一化对比图（估值节专用）
- 归一化起点：2018 年初或上市首日（取较晚者）
- 末点价格 = 正文估值引用日的收盘价（铁律：图文数字必须对齐）
- 图存 `charts/{code}_归一化_股价vs利润TTM.png`
- 图后必须紧跟图读法解读 + 节内锚句

**一键出图脚本（固化工具）**：
- **港股**：`python3 scripts/generate_charts_hk.py {代码} {公司名} [--latest-h1 净利] [--latest-price 现价]`
- **A 股**：`python3 scripts/generate_charts_a.py {代码} {SH|SZ} {公司名}`
自动拉取历史财务+日频股价、计算 TTM、对齐价格，生成标准白底归一化图与双 Y 轴图。

**PE 百分位数据获取**（瀑布式降级）：
1. **首选 10 年**：尝试获取近 10 年日频 PE-TTM（东财接口 → AKShare/Tushare 补充）。数据覆盖 ≥9.5 年时报"近 10 年 X% 分位"
2. **不足 10 年**：取上市以来全部日频 PE-TTM → 报"上市以来（YYYY 年起，约 N 年）X% 分位"
3. **上市不足 3 年**：放弃分位，只报当前 PE + 同业横向对比

数据源详见 `references/行情与PE数据源.md`。港股公司走港股数据源路径。

**API 调用失败时的降级流程**：
1. 如果直接调用 API 失败（网络错误、404、429 等），**先查阅 `~/Documents/AI-Investment/investment/data-api/` 中的参考实现**，确认正确的 URL 格式和参数
2. 按优先级尝试多个数据源（东财 → Yahoo → 新浪 → 腾讯）
3. 如果所有数据源均失败，跳过图表生成，在文章中标注"历史股价数据暂不可用，图表待补充"
4. G5/G6 硬门禁在网络故障时可豁免，但 G1-G4 仍需满足

### 步骤 4：按四问框架写文章

**骨架固定（6 节 + 表 + 文末话术），顺序不变：**

```
标题：{公司}（{代码}）{期数} 财报速览——标题直接写判断
报告期/披露日/数据来源声明（引用块，一句话）
一句话结论（判断式 ≤2 句，全篇唯一允许抓眼球处）
核心业绩看板 / 封面图（紧跟结论，16:9横版卡片，3秒看懂核心矛盾与底牌）
主要指标速览表（紧跟看板，~10 行，跨期对账用途）
一、它赚不赚钱？——利润表
二、赚到的钱到手了吗？——现金流量表
三、家底厚不厚？——资产负债表（含排雷检查）
四、明年还能赚吗？——看未来（增长引擎/排雷/股东回报）
红绿灯速判（每行只列"结论标签+关键数字"）
估值与观察点（归一化图 + PE + 分位 + 利润方向 + 观察点）
**估值与观察点**——这是全文的分析重心，必须包含以下六个子要素，缺一不可：

1. **归一化图 + 图读法**：插入归一化对比图，紧跟一段文字解读（相关系数、股价涨幅、利润涨幅）
2. **PE 分位**：当前 PE-TTM 在历史中的位置。必须包含：
   - 当前 PE 值 + 分位百分比（优先运行 `python3 scripts/fetch_valuation.py {代码}` 获取官方实时数据）
   - 逐年 PE 变化表（至少 4 年），展示估值演变脉络（如 2021: 72x → 2024: 28x → 当前: 23x）
   - 分位标注格式：`同花顺近5年 / 上市以来（YYYY 年起，约 N 年）X% 分位`，严禁窗口混淆
3. **利润方向判断**：未来 2-3 年利润增速预期（加速/稳定/放缓），给出具体驱动因素和约束条件
4. **市场定价逻辑**：解释当前估值水平的市场担忧/预期，不能只说"杀估值"或"估值压缩"而不解释原因
5. **观察点表格**：按时间维度列出下个季度/全年需要验证的关键变量
6. **估值情景推演（严禁单一目标价）**：
   - **修复情景**：若悲观预期改善、利空出尽，估值修复至历史估值中低位分位（如 15%~25% 分位 PE），对应的理论价格/空间；
   - **磨底/防守情景**：若价格战或成本压力持续，估值维持历史极低区间的防御边界；
   - **红线**：严禁给出“目标价 XX 元”的主观推票式武断结论，必须用条件化情景呈现客观参考。

**反模式**：
- 估值段只写"PE X 倍，处于历史低位" + "市场在担忧什么"两条 bullet → 太笼统。必须用逐年 PE 表展示估值变化全貌，用利润方向给出前瞻判断。
- 给出单一目标价（如“目标价 45-50 港元”）→ 严重违规，充满荐股推票味。必须改用双情景推演。

同业锚点（可选，详见 references/peer_benchmark.md）
文末话术（固定两段，逐字使用）：
  如果您觉得这篇文章有启发，欢迎点赞、转发、关注！
  风险提示：本文仅供参考，不构成投资建议。市场有风险，入市需谨慎。
```

**主要指标速览表规格**（~10 行封顶）：
- 通用核心行：营业收入、归母净利润（A股加扣非）、整体毛利率、经营现金流、净现金、公司特色跟踪行 1-2 条、分红率、PE(TTM)+分位
- 删掉的行：总资产、货币资金+有息负债（净现金一行含构成即可）、基本每股收益、加权 ROE（期间口径跨期不可比）、市值
- 分红用**分红率**（=分红/归母），每股金额放备注列
- 净现金行带构成："现金 X 亿 vs 有息负债 Y 亿"，口径写表注
- 裸数字与正文判断冲突时加脚注编号，表下注说明

**每问只回答该问的事。** 现金流不在资产负债节重讲，排雷结论统一放红绿灯。

**直接写发布稿，不产中间态。** 推算与归因当场用自然句写清（"单季=中报−一季报""财报没有解释原因"），来自财报的数字直接陈述。

文件命名：`{公司}_财报速览_{期数}.md`，存入 `{代码}_{公司}/reports/`；在 `财报速览/README.md` 索引页登记一行。

### 步骤 5：走 checklist + 硬门禁

加载路由对应的 checklist（A 股 / 港股），逐项过一遍。其中 **6 条硬门禁** 必须产出校验证据才能发布，详见 `references/pitfalls/hard_gates.md`：

| # | 硬门禁 | 校验证据 |
|---|---|---|
| G1 | PDF 已下载并 read_file 提取 | 引用 PDF 具体页码 |
| G2 | 核心比率已 execute_code 复算 | 脚本输出 |
| G3 | 市值/PE 已实测，标注日期和来源 | API 返回值 |
| G4 | 归一化图末点价格 = 正文现价 | 两者数值对账 |
| G5 | 归一化图已生成并插入估值节 | 文件路径存在 |
| G6 | 核心业绩看板已生成并插入结论下方 | 文件路径存在且作为文章封面 |

条件触发的 pitfall（汇兑、存货结构、税项附注等）由路由后的 checklist 引导，详见 `references/pitfalls/conditional.md`。

### 步骤 6：收尾

**全文勾稽检查（不可跳过）**：完成初稿后，用 `grep -n` 或 `search_files` 搜索报告中所有出现的数字（如 TTM 利润、净利润、营收等核心指标），确认全文数值一致。常见错误：结论段用了旧版数据（如 TTM 135 亿），而计算段用了修正后数据（如 TTM 171 亿），两者相差甚远但未统一。

过一遍 writing_style 规则（已前置在下方），确认无需修改。

## 写作风格（前置规则，写作时直接遵守，不需事后 humanizer）

| 规则 | 要求 |
|---|---|
| 段落长度 | ≤120 字，超过就拆 |
| 句长 | 逗号串联不超过 3 个分句，单句 ≤35 字（术语注解豁免） |
| 禁止开头 | "值得注意的是""需要指出的是"等引导式开头 |
| 禁止收尾 | "综上所述""总而言之" |
| 术语首现 | 配一句大白话，如"商誉（通俗说：收购时多付的溢价）" |
| 判断句式 | 用立场句不用问句："分位很低，但低得有水分" ✓ / "25.9倍贵不贵？先看分位" ✗ |
| 证据分级 | 确认→直接陈述；推算→算式揉进句子；未定论→自然限定语（"财报没有解释原因"） |
| 人名纪律 | 方法论归属点名一次，后续用代词/直陈；名言查出处再挂名 |

## 证据分级（内化于行文，不贴标签）

| 级别 | 含义 | 发布稿写法 |
|---|---|---|
| 确认 | 公司披露的报表/附注原值 | 直接陈述 |
| 推算 | 由披露值计算 | 算式揉进句子："单季=中报−一季报" |
| 未定论 | 财报无法证实的归因 | 自然限定语："财报没有解释原因""没有能验证这一点的数据" |

头部统一声明：数据来源 + 单季口径 + 行情实测日期。非公司披露信息标注"（非公司披露，仅供参考方向）"。
