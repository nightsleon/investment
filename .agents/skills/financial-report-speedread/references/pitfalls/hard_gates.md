# 硬门禁（5 条，不过不发）

## G1：PDF 已下载并 read_file 提取

**要求**：财报 PDF 已下载到本地，用 read_file 提取了关键页面文本。

**校验证据**：文章中引用 PDF 具体页码（如"利润表 P128"、"附注六 P45"）。如果全文没有页码引用，说明没真正读过 PDF。

**常见翻车**：
- 只读了新闻稿/摘要，没读全文 PDF
- 读了摘要 PDF（4-6 页）而非全文（100+ 页）——摘要只有主要会计数据，四问分析不够
- 港股公司只读了"中期业绩公告"（精简版），没读完整"中期报告"

## G2：核心比率已 execute_code 复算

**要求**：毛利率、净利率、收现比、同比增速、单季数据等关键比率，必须用 execute_code 从 PDF 原始数字复算，不可直接引用新闻或凭印象。

**校验证据**：工作区中有复算脚本或中间结果文件。

**常见翻车**：
- 新闻说"Q2 净利 24.67 亿"，PDF 倒算（H1−Q1）实为 23.70 亿——新闻口径不同
- 毛利率"60.9%"直接抄新闻，实际 PDF 里是 60.86%，四舍五入方向不同
- 单季数据抄了同花顺/东财网页值，与 PDF 不一致

## G3：市值/PE 已实测，标注日期和来源

**要求**：现价、总市值、PE(TTM) 必须从数据接口实测，注明查询日期。PE(TTM) 必须结合财报披露日 TTM 净利与实时汇率核验，并明确标注分位数统计窗口（近 3 年 / 近 5 年 / 上市以来）。

**校验证据**：文章头部或估值节有"市值、PE 按 X 月 X 日收盘实测"声明，附带数据源与分位窗口。

**一键实测工具（首选推荐）**：
```bash
python3 scripts/fetch_valuation.py 代码
# 自动兼容 A 股与港股，直连东财/腾讯官方接口，自带港币/人民币动态汇率折算与官方 PE(TTM)
```

**港股跨币种核验铁律**：
```
PE(TTM) = 当日总市值（港币 HKD）× 当日汇率（HKD/CNY）÷ TTM 归母净利润（人民币 RMB）
```
- 港股必须使用**当日实时外汇中间价**，严禁使用粗略静态汇率（如 0.90）一刀切
- 历史回测必须遵守 **Point-in-Time (PIT) 财报披露日生效原则**，严禁以 6/30 或 12/31 期末日提前调高 TTM

**常见翻车**：
- 用了 f162（动态 PE）当 TTM，差 20%+
- 市值推算而非实测（曾把 2042 亿写成 3300 亿）
- 港股全历史使用单一固定汇率（如 0.90）回测，导致历史估值曲线严重变形
- 港股半年报利润在 6/30 次日就提前生效（前视偏差），把 7~8 月正常 PE 误算为低估，导致历史分位失真（如把 0.81% 算成 3.2%）
- 分位数未标明时间窗口（读者在同花顺看“近5年”，报告算的是“上市以来全部”，分母不同产生误解）

## G4：归一化图末点价格 = 正文现价

**要求**：归一化图中最后一个数据点的股价，必须等于正文估值节引用的现价。两者必须是同一交易日。

**校验证据**：图注中标明"股价截至 X 月 X 日"，且该日期与正文"按 X 月 X 日收盘实测"一致。

**常见翻车**：
- 图停在报告期末（如 6/30 的 135.83 元），正文用 9/2 现价 168.06 元——图文数字打架
- 图注写"股价涨 1.1 倍"（基于 6/30 价格），正文说"涨 1.4 倍"（基于 9/2 价格）

**修法**：出图脚本最后一步，把末行价格覆盖为最新交易日收盘价，重新出图。
