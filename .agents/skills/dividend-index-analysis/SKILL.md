# 红利类指数分析与对比

## Overview

用于评价红利类指数本身是否优秀，以及比较不同红利指数。

核心原则：

> 编制规则决定指数未来会持有什么，历史数据负责验证规则是否有效。

严格区分三个问题：

- 指数质量：本 skill 的范围；
- 当前是否值得买：看估值与买入时机，不纳入指数质量评分；
- 选择哪只基金或ETF：看费率、规模、流动性和跟踪质量，另行分析。

## When to Use

适用于红利、高股息、红利成长、质量红利、红利低波等策略指数的：

- 单指数评价；
- 多指数横向比较；
- 官方编制方案解读；
- 长期全收益、波动、回撤与稳定性验证；
- 面向普通读者的比较文章。

不要用于个股分析、当前估值判断、择时或ETF产品选择。

## 默认评价框架

红利质量、红利低波、经典红利和跨市场红利解决的问题不同。综合评价不能把某一种策略特征设成所有指数的必答题，例如不能让纯质量指数仅因没有低波筛选固定失分。默认使用五维框架：

| 维度 | 权重 | 核心问题 |
|---|---:|---|
| 规则稳健性 | 30% | 分红是否可持续，能否过滤高股息陷阱，规则是否服务于指数自身目标 |
| 历史风险收益 | 25% | 长期全收益、最大回撤和风险收益效率是否有竞争力 |
| 表现稳定性 | 15% | 收益是否依赖少数年份，中长期路径是否稳定 |
| 结构分散 | 10% | 个股和行业是否集中，规则护栏与实际持仓是否一致 |
| 证据可信度 | 20% | 数据是否同口径，发布后历史是否充分，官方资料是否一致 |

这套权重用于跨类型综合比较。结构权重低于证据可信度，避免仅凭行业上限或单期快照反超规则与历史更扎实的指数；发布后真实历史、数据可比性和资料一致性承担更大作用。若任务只比较同一子类型，可在说明目标后微调，但不得为得到预设冠军倒推权重。详细评分、证据等级和计算口径见 `references/scoring-and-metrics.md`。任务限定只用指数公司/交易所官网，或需要核验现行方案、修订公告、动态接口、全收益代码、历史下载及最新结构时，先加载 `references/official-index-source-verification.md`，按“现行PDF→详情页→修订公告→动态接口→数据服务”的证据链执行。研究中证指数时再加载 `references/csi-official-index-research.md` 获取中证专用页面和接口。把港股通、沪港深或其他跨市场指数放入同一比较时，加载 `references/cross-market-index-comparison.md`，处理币种、混合交易日历、发布前回溯、市场权重与行业集中。使用跟踪ETF的定期持仓补充指数结构，或分析“行业迁移→收益/回撤→分红可持续性”时，加载 `references/etf-holdings-proxy.md`；同花顺移动端页面可直接运行 `scripts/collect_10jqka_etf_holdings.py`。

## Workflow

### 1. 锁定比较口径

先记录每只指数的：

- 指数代码与准确名称；
- 币种；
- Price、TR或NTR口径；
- 数据起止日与交易日数；
- 基日、历史起始日与正式发布日期。

红利指数长期比较优先使用同币种、同日期的全收益序列。中证全收益通常对应标普TR，不要与价格指数或NTR混比。跨市场指数可能因交易日历不同而比纯A股指数多出观测日；统一起止日即可，不要为追求相同行数删除官方交易日。单指数CAGR和回撤使用各自完整序列，滚动稳定性优先按月末点位；只有相关性或组合收益才另取共同交易日交集。若官方全收益代码和序列经过官网清单、详情页、接口及数据服务仍无法核实，不得按代码规律猜测，也不得把价格指数冒充全收益；用户要求保留该指数时，可单列长期跟踪ETF的含分红复权净值作为临时代理，必须标注“已扣费、受跟踪误差影响、非官方全收益”，降低证据与评分置信度，且不得用细小差异作结论。

### 2. 拆解编制规则

按统一链条写清楚：

`样本空间 → 流动性 → 连续分红 → 盈利/支付率/股息增长 → 高股息 → 低波 → 加权与封顶 → 调样`

重点检查：

- 股息率用近12个月还是多年平均；
- 是否要求连续分红；
- 是否约束盈利、支付率、现金流或每股股息增长；
- 是否防范股价暴跌或周期顶部制造的高股息；
- 低波是筛选条件还是加权因子；
- 单股与行业上限是否写在现行规则中；
- 调样频率和缓冲机制是否容易造成高换手；
- 新旧官方资料对规则的描述是否一致。

每只指数只提炼一个核心优势和一个核心代价，不照抄整份编制方案。

### 3. 验证历史风险收益

至少计算：

- 精确年化全收益；
- 年化波动率；
- 最大回撤；
- 回撤高低点与修复时间（数据允许时）；
- 年化收益÷年化波动。

“收益÷波动”只是直观效率指标，不能冒充夏普比率。夏普比率必须统一无风险利率和数据频率。

### 4. 检查表现稳定性与证据可信度

十年CAGR不能单独代表稳定性。继续检查：

- 完整年度正收益次数与最差年度；
- 分年度收益是否由少数年份贡献；
- 滚动3年、5年年化收益中位数与正收益占比；
- 指数发布前回溯与发布后真实历史的比例；
- 不同市场阶段的表现；
- 官方序列、ETF代理和编制方案是否同口径且前后一致。

滚动窗口高度重叠：相邻月度滚动5年窗口共享59个月，不能当成多次独立检验。稳定性评分以完整年度为主，滚动3年为辅，滚动5年只补充路径信息。

发布日之前的数据必须标注为回溯试算。历史风险收益只评价序列成绩；回溯占比、发布后长度和资料不一致统一放入“证据可信度”，避免同一缺陷在收益、稳定性和证据中重复扣分。基日或历史起始日不等于发布日期。

### 5. 分析结构与收益来源

检查：

- 成分股数量、最大个股权重、前十大权重；
- 规则中的个股和行业上限；
- 最新行业权重与主要周期暴露；
- 收益是否可能依赖银行、能源、煤炭、公用事业等少数行业；
- 规则所解释的收益来源是分红质量、盈利增长、低波还是周期高股息。

必须区分“规则护栏”和“实际结构”：有行业上限不等于当前一定分散，没有行业上限也不等于当前一定集中。尽量使用同日完整持仓和行业权重；资料不齐时只评价已核实的护栏，并给结构证据标级：A=完整同日个股与行业数据，B=部分实际结构加规则约束，C=主要依赖规则约束。证据较弱时不得给出“结构最均衡”等确定结论。

如果缺少历史成分股、行业权重或基本面序列，必须说明证据边界：不得用当前持仓倒推十年结构，也不得虚构股息、盈利增长与估值变化的精确收益归因。

跟踪ETF只能作为代理线索。写入文章或改变结构评分前，先确认披露的是完整持仓还是前十大、行业比例的分母、报告期覆盖率及ETF与指数的跟踪偏差。数据不完整时先汇报可用范围和限制，未经用户确认不更新文章；若用户要求回滚，只撤销该轮代理数据引入的内容，不连带回滚已认可的框架和其他改写。

### 6. 评分并形成判断

- 各维度不超过默认权重；
- 规则稳健性评价“是否做好自身目标”，不得把低波、质量或跨市场中的任一特征设成所有指数的必答题；
- 分项之和必须等于总分；正文出现总分时必须同时公开一级维度、权重和一级得分，详细子项可放附录或评分明细文件，不能只报总分；
- 规则与结构等判断项应注明评分锚点，通常承认约1分误差；
- 总分相差1—2分视为同档，优先使用“综合领先组、特色鲜明组、单列观察”等非硬排名分组；
- ETF代理只够判断大致档位时，给总分区间或置信度，不制造单点精度；
- 回溯占比较高或资料不一致时，只在证据可信度中扣分，避免重复处罚；
- 规则不成立时，不能仅凭漂亮回测给出优秀结论。

评分是特定框架下的横向比较，不是收益预测，也不是绝对投资评级。面向公开发布的文章应写成独立首发文本，不出现“旧版、重新调整、原评分”等依赖修订背景的说法。

### 7. 管理文档版本与交付物

先判断用户说的是“修改原文”还是“重新输出一份文档”：

- “重新输出一份”默认创建新文件，不直接覆盖原文；文件名无法确定时采用清楚的新版后缀，并在交付时列明新旧文件。
- 用户明确要求在原文上修改时，覆盖前先保存原稿为同目录 `原文件名_old.md`，除非用户明确不要备份。
- 如果已经误覆盖，立即从会话附件、历史版本或补丁记录恢复 `_old.md`；不要只复制修改后的文件再声称它是旧版。
- 新旧稿必须做区分性验证：检查标题、评分框架、关键总分/结论等版本标记，同时确认新版内容未被回滚。
- 若评分CSV、图表或其他派生物也随框架变化，文件名或说明必须能对应新旧版本，避免旧文引用新版评分或反之。

## Output

长文面向普通读者时，优先按“先看买成什么，再解释为什么”的顺序组织：

1. 有真实矛盾的标题；
2. 开头给出2—3个反常结果，例如收益冠军、回撤冠军和风险收益效率冠军不是同一只，并给综合分组；
3. 先展示最新持仓、行业暴露和集中风险，回答“规则最后买成了什么”；
4. 用一张表比较全收益、波动、回撤和风险收益效率；
5. 用通俗语言解释分红不是白捡、高股息陷阱、质量与低波的区别；
6. 按红利质量、红利低波、成长低波、经典红利等策略类型压缩规则，每只只保留“怎么选、优势、代价”，完整链条放附录或来源；
7. 比较发布前回溯、发布后表现和稳定性，并说明滚动窗口重叠；
8. 公开五维权重、一级维度得分和总分，以梯队为主要结论；详细子项、证据等级和代理误差放附录或独立评分明细；
9. 用“目标导航”帮助读者按任务定位指数：每条无序列表以加粗投资目标开头，随后写“优先研究对象 → 适合原因 → 必须接受的代价”；内容较多时不要塞进四列宽表；
10. 明确目标导航只用于找到值得进一步研究的指数，不等于直接买入建议；估值与ETF费率、规模、流动性、跟踪质量仍需另行判断；
11. 将数据口径、代理限制、结构归因边界和官方来源放在文末。

第一次出现时写指数全称，后文使用清楚且唯一的简称，避免长名称反复打断阅读。全文只选一套核心比喻（例如比赛/选手），不要同时混用赛跑、考试、尺子、开车等多套比喻。正文让文字负责结论、表格负责精度：一段通常只保留1—2个关键数字，其余进入表格。

写作采用“事实 → 判断 → 含义”，少堆术语。可用贴切比喻解释抽象区别，但不能让趣味性替代证据。总分或分组一旦出现，正文必须同时提供维度、权重和一级得分；详细子项可在附录或评分明细中复核。文章按首次发布的独立文本写作，不使用“仍是、重新、原评分、新版”等需要读者知道旧稿的表达。遇到多个指数同日触底、同阶段同步变化等反常或容易困惑的数据，要补充共同市场环境、底层暴露和事件机制，不能只列数字。

ETF持仓变迁单篇文章额外遵循：

- 开头第一次出现时写基金全称、代码，并声明中文简称；后文只用中文简称或“这只ETF”，不反复出现代码和全称。
- 图表紧跟其直接支撑的章节，不在文末集中堆图：行业迁移图放持仓变化后，复权价格与回撤图放阶段收益表后，盈利与支付率图放分红表后。
- 每篇通常控制在3张核心图；标题保持中性，结论写在正文，图下注明前十大代理、复权口径和非因果归因边界。
- 生成后逐张做视觉验收，重点检查末期横轴标签、右上角注释、最大回撤标签和长负值标签是否重叠或裁切。

详细图表设计与插入规范见 `references/etf-holdings-proxy.md`。

## Hard Rules

- 只评价指数，不混入当前估值、买入时机或ETF质量。
- 只用全收益或净总收益做红利策略长期主比较，价格指数只作辅助；官方全收益无法核实而用户要求保留指数时，只能按Workflow第1步单列ETF含分红复权净值临时代理并降置信度。
- 不混用币种、日期、税收口径或Price/TR/NTR。
- 不把回溯数据写成实盘历史。
- 不因十年收益第一就判定指数质量第一。
- 不把“低波”写成“不会跌”。
- 不把成分股数量等同于分散度。
- 不根据当前行业权重反推规则上限。
- 不把ETF前十大持仓或其内部行业占比写成指数完整行业权重。
- 不对缺失的历史结构和收益来源做精确归因。
- 不用评分掩盖规则缺陷或数据限制。

## Verification Checklist

- [ ] 比较口径、日期、币种与回报类型一致
- [ ] 编制规则来自现行官方方案
- [ ] 使用全收益或净总收益序列
- [ ] 区分基日、历史起始日和发布日期
- [ ] 计算收益、波动、回撤与滚动稳定性
- [ ] 检查个股和行业集中度
- [ ] 明确结构与收益归因的证据边界
- [ ] 五维权重为30/25/15/10/20，或已说明同类比较的调整理由
- [ ] 规则按各指数自身目标评价，没有把低波或质量设成通用必答题
- [ ] 历史成绩与证据可信度分开，回溯问题没有重复扣分
- [ ] 滚动窗口已说明重叠性，未当作独立样本
- [ ] 结构护栏与实际持仓分开，资料不齐时标注A/B/C证据等级
- [ ] ETF代理使用区间或低置信度表达，没有伪精确单点结论
- [ ] 全部子项加总、排序/分组和正文结论一致
- [ ] 文章按独立首发文本写作，未残留修订历史措辞
- [ ] 未混入估值择时或ETF工具质量
