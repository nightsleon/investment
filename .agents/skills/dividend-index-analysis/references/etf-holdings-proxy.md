# ETF持仓作为指数结构代理

用于指数公司缺少历史成分/权重，而存在长期跟踪ETF定期持仓时。ETF数据只能补充结构线索，不能替代指数官方历史成分。

## 一、先做完整性门禁

采集后、写文章前必须回答：

1. 覆盖哪些报告期，是否连续？
2. 每期是完整持仓、半年报/年报全部股票，还是季度前十大？
3. 持仓权重的分母是基金净值、股票资产还是披露持仓合计？
4. 行业比例是全基金行业权重，还是前十大内部归一化占比？
5. ETF采用完全复制、抽样复制还是优化复制？
6. 现金仓位、申赎、停牌、跟踪误差和披露日期是否可能造成代理偏差？
7. 数据是否足以支撑目标结论，例如“主要权重股变化”还是“完整行业结构变化”？

门禁不通过时：只归档数据并报告限制，不改文章、不改结构分。用户习惯先讨论再改Markdown，必须等确认。

## 二、移动端动态页面的接口发现

页面本身只有Vue容器时：

1. 下载HTML，定位业务JS文件；
2. 下载压缩JS，搜索 `axios`、`fundCode`、`position`、`heavyStock`、`reportDate` 等字符串；
3. 查清请求方法、相对路径和参数名；
4. 用移动端User-Agent与页面Referer复现请求；
5. 保存原始JSON，再生成整理表，避免只保留二次加工数据。

不要保留分享链接中的用户ID、分享ID或其他跟踪参数；底层公开接口通常只需基金代码。

## 三、同花顺512890案例

页面：华泰柏瑞红利低波ETF持仓回顾。

底层请求：

```text
GET https://fund.10jqka.com.cn/bff-server/v1/fund/position_rank?fund_code=512890
```

关键结构：

```text
data.pastYearRate[报告期]
  ├─ heavyStock[]             前十大持仓
  │    ├─ sec_code / sec_name
  │    ├─ industry            同花顺宽口径行业
  │    └─ marketValueRatio    占基金净值比例
  ├─ share_per                前十大占基金净值合计
  ├─ shareClassPosition[]     前十大内部行业构成
  │    ├─ industry
  │    └─ rate                内部归一化占比
  └─ reportDate
```

本次接口返回2019Q1—2026Q2共30个有效季度，每期10只股票。`heavyStock.marketValueRatio`之和等于`share_per`；`shareClassPosition.rate`每期合计100%，因此它是前十大内部行业构成，不是全基金行业权重。

## 四、一键采集

在线采集任意基金代码：

```bash
python3 .agents/skills/dividend-index-analysis/scripts/collect_10jqka_etf_holdings.py \
  512890 \
  --output-dir ./sources/etf-position-proxy/512890
```

使用已保存的原始响应离线复算：

```bash
python3 .agents/skills/dividend-index-analysis/scripts/collect_10jqka_etf_holdings.py \
  512890 \
  --input-json ./512890_position_rank_raw.json \
  --output-dir /tmp/512890-verify
```

批量比较多只ETF时，按基金代码分别建目录并逐只运行同一脚本；不要把不同基金的原始响应混在一个文件中。批量结果另建覆盖汇总表，至少包含ETF与指数名称、接口报告期数、空报告期、有效报告期数、起止报告期、持仓行数、相邻期变化行数和前十大占基金净值范围。先完成各基金完整性核验，再比较名单稳定性或结构迁移。

脚本只需Python 3标准库和系统 `curl`，会输出原始JSON、季度前十大持仓、前十大行业构成和相邻季度名单变化。基金代码只作为接口参数与文件名前缀，不保存分享链接中的用户参数。

## 五、建议输出

至少保留：

1. 原始接口响应；
2. 季度前十大明细：报告期、排名、代码、名称、行业、基金净值权重、前十大合计；
3. 前十大行业构成：内部归一化占比与实际基金净值占比同时列示；
4. 相邻季度名单变化：连续保留、新进入、退出前十大；
5. 数据说明：来源、覆盖、分母、行业口径和代理限制；
6. 可重复采集脚本及ad-hoc验证。

“新进入/退出”仅表示进入或离开前十名，不能表述为基金买入、卖出或清仓。历史名单变化可用于观察主要权重股和风格重心，不能计算完整行业集中度或精确收益贡献。

## 六、验证

程序检查：

- 每个有效报告期是否恰有10条重仓股；
- 每期 `sum(marketValueRatio)` 是否约等于 `share_per`；
- 每期 `sum(shareClassPosition.rate)` 是否约等于100%；
- 按股票行业汇总后的前十大内部占比是否与接口行业比例一致；
- 报告期是否排序、是否存在空期和断档；
- 整理表行数是否等于有效报告期数×10；
- 原始文件和输出中是否误存分享用户参数。

若写了采集脚本且项目没有统一测试命令，创建一个真实的临时验证脚本文件：通过系统临时目录API（如Python `tempfile.mkstemp`）生成文件名以 `hermes-verify-` 开头的 `.py` 文件；脚本应对每只ETF使用已保存原始JSON离线复算，并断言：有效期数×10等于持仓行数、变化行数等于有效期数−1、重算文件与已归档文件校验和一致。执行成功后删除验证脚本和临时输出。最终明确写“专项/ad-hoc验证通过”，不要称“测试套件全绿”。仅创建同名前缀的临时目录不能替代临时验证脚本文件。

## 七、文章与回滚纪律

- ETF数据必须明确标为“跟踪基金代理数据”。
- 只有前十大时，默认只能讨论主要权重股，不能写完整行业持仓；若用户明确接受其作为临时结构代理，可据此描述核心行业迁移，但仍须保留“前十大内部占比、非完整持仓”的醒目标注。
- 行业分类与指数公司口径不一致时，不静默映射。
- 新数据若不足以改变结论，不为了增加表格而硬写入文章；若只是强化原判断，可保留原分数并解释证据为何增强。
- 对多个指数同日触底、同步回撤或行业突然切换等读者容易疑惑的现象，补充市场环境、共同底层暴露和机制解释，不只陈列日期与数值。
- 用户指出数据不全时，先停止扩展结论；若要求回滚，只删除该次代理数据产生的文章、资料和skill改动，保留此前已认可的分析框架。

## 八、长期投资分析主线

ETF历史持仓文章按以下顺序组织，不从涨幅或当前高股息率直接下结论：

`行业迁移 → 调整后价格的收益与回撤 → 当前持仓盈利质量 → 分红可持续性 → 长期复核项`

### 1. 先划分行业阶段

- 用季度前十大内部行业构成识别主导行业，阶段边界写明实际报告期；
- 同时列出代表性股票、前十大占基金净值合计及相邻期名单重合数；
- “新进/退出前十”只说明名次变化，不写成买入、卖出或清仓；
- 主导行业从基建、周期转向金融时，解释筛选规则为什么会选中这些行业，而不是把指数写成固定风格。

#### 长期底仓优先于逐季名单复述

个股变化按以下优先级分析：

1. **长期底仓：**统计进入前十大期数、最长连续期数、出现期间平均/最高ETF净值权重、首次/最近报告期；正文重点分析出现次数最多的5—6家公司。
2. **新进与退出：**只用一小段说明平均保留数量和少数大换血季度，不逐季罗列。
3. **极端权重：**只标单股历史最高权重及其对应阶段，判断个股集中是否可能放大波动。

“长期高频”只表示反复进入季度前十大，不等于基金全程连续持有，更不自动等于优质公司。质量判断必须回到商业模式、稀缺资产/护城河、利润与现金流稳定性、资本开支、负债和支付率；明确区分“稳定现金流底仓”与“周期高股息资产”。资源、石化、铁路等公司即使高频出现，也可能只是长期符合高股息和低波筛选，不是持续复利公司。

评价长期底仓时可使用各公司自身的长期盈利趋势，但不能把这些公司CAGR加权成ETF历史组合CAGR。表格优先展示出现期数、连续期数、平均/最高权重、最新完整年度利润同比和支付率。

### 2. 再对照收益与回撤

- ETF价格必须使用复权价格或官方复权净值；裸价格会把现金分红除权误写成亏损；
- ETF文章需要评价指数收益的实际交付时，基金侧优先使用累计净值或复权净值，指数侧使用税前全收益指数，并严格对齐起止交易日；二级市场前复权价格只能写成持有体验差异，不能冒充官方跟踪差；
- 年化跟踪差=`基金年化收益－全收益指数年化收益`；年化跟踪误差=`日收益差标准差×√250`，两者必须分开报告；
- 使用累计净值前检查现金分红和份额拆分：无现金分红时累计净值可直接跨拆分比较；存在现金分红时需按分红再投资构造基金总回报序列；
- 同时报告上市以来和近5年。上市初期建仓、复制偏离与起点会使全周期正负差异常，不能把早期正差外推为持续超额收益；
- 毫秒时间戳要按行情市场时区转换。A股雪球数据使用 `Asia/Shanghai`；若按UTC直接取日期，会把交易日误写成前一天；
- 使用外部价格文件前先检查文件内部证券代码，不能依据文件名或截图标签认定数据属于目标ETF；
- 各阶段长度不同时，同时展示累计收益、CAGR和最大回撤，不能只比累计涨幅；
- 阶段边界来自持仓快照，只能说明风格变化与收益是否同步。季度前十大无法证明调仓导致随后涨跌；
- 精确个股/行业收益贡献需要每日完整权重、调仓路径和同期证券收益。资料不足时，只写“时间上重合、暴露方向一致”；
- 最大回撤若与某类行业高度集中同期出现，应补市场事件和行业机制，但保留因果边界。

### 3. 最后检查分红是否可持续

对最新前十大使用最近完整年报，至少整理：

- ETF净值权重；
- 最新完整年度归母净利润同比；
- 公司自身3—5年利润CAGR（只用于逐家公司判断长期盈利质量）；
- ROE；
- 基本EPS；
- 同一报告年度的每股税前分红，含中期与年末方案；
- 估算支付率：`年度每股税前分红 ÷ 基本EPS`。

可按最新ETF净值权重汇总最新年度利润同比、ROE和支付率，且必须标注这是“当前持仓静态质量指标”，不代表ETF历史组合利润增长。**不要汇总或加权各公司3—5年CAGR**：ETF历史持仓不断变化，当前权重加权的公司CAGR既有幸存者偏差，也不是数学意义上的组合利润CAGR。若要分析ETF历史盈利变化，必须按每个历史时点的实际持仓和权重逐期复算。

把主导行业与其他行业分开。银行组合还要检查净息差、资产质量、资本充足率和支付率；非银行高支付率公司要结合利润与现金流。支付率有余量不等于风险分散，多个银行可能受同一宏观变量影响。

区分两种“分红持续”：

1. 同一家公司能否持续提高分红；
2. 指数能否通过调样不断换入新的高股息公司。

红利指数可能靠第二种方式维持组合股息，因此长期持有者买到的是规则驱动的行业轮动，不是一组永不更换的分红公司。

### 4. 文章写法

- 标题写清持仓主线，例如“从地产、煤炭到银行”，不要用泛化的“深度分析”；
- 基金首次出现写完整名称、代码并定义中文简称；后文只用中文简称或“这只ETF”，不重复代码和全称；
- 开头按“反差或真实困惑→核心结论→数据口径”展开。先回答读者最关心的问题，再交代前十大代理和价格口径，避免方法说明打断开场；
- 内容较完整时优先使用六段闭环：`为什么换（规则）→换了什么（行业阶段）→谁留下（长期高频公司）→赚了多少且ETF交付多少（收益、回撤、跟踪差）→当前分红能否持续→以后看什么`；
- 用户要求重点判断优质底仓时，把“长期高频公司”设为独立章节，不埋在行业阶段里。高频只代表多次进入前十大；必须区分稀缺资产与稳定现金流公司、周期高股息公司，并说明当前财务数据不能倒推历史进入或退出原因；
- 行业构成图紧跟行业迁移章节；收益回撤和跟踪差放在同一章，标题同时覆盖“持仓赚多少”和“ETF交付多少”；
- 正文用少量阶段表和关键股票讲故事，避免季度数据逐期堆砌。表格已经展示的数字不在正文逐项复述，完成初稿后主动压缩约10%—15%；
- 结论回答：哪一阶段赚钱、哪一阶段承担主要回撤、当前分红靠什么支撑、规则能否及时替换衰退的高股息来源、未来应盯什么；
- 对异常共同低点、行业突然切换、价格文件代码不匹配等读者会追问的地方，当场解释原因；方法限制优先放在表注或图注，不要在正文反复打断叙事；
- 做去AI味检查：删除“其他几点简要看即可”“实际历史交付结果”等报告腔或元话语，少用机械三段论、过量加粗、“这意味着”“总体来看”和泛泛的正反两面结论；过渡直接写“看完换仓，再看这些变化有没有带来收益”；
- 技术词要用通俗句解释：跟踪差看长期少赚或多赚多少，跟踪误差看每日跟得稳不稳。费率、交易成本和负跟踪差会侵蚀回报；不要写“跟踪误差会吃掉回报”。

### 5. 图表设计与插入

每篇优先使用3—4张核心图，不用多期饼图，也不为了“图文丰富”绘制与主线无关的规模、成交额图：

1. **季度前十大行业构成：**保留全部季度数据并绘制100%堆叠面积图，放在持仓迁移章节后；纵轴固定0%—100%，图例颜色稳定，副标题注明“前十大内部归一化占比，非完整ETF行业权重”。低频行业可合并为“其他”，但消费等重要历史主线不要静默合并。直线边界过于锯齿时，可用 ECharts `smooth: 0.25—0.35` 只平滑季度点之间的连接，不做移动平均；图中明确披露该口径，最新标签仍使用最后一期原始值。
2. **复权价格与回撤：**上方画上市日归一为100的复权价格，下方单独画回撤；用浅色背景标出持仓阶段，放在阶段收益表后；图注声明阶段边界只用于观察同步关系。
3. **基金净值与全收益指数：**需要评价ETF交付时，上方画同日起点归一为100的基金累计/复权净值和税前全收益指数，下方画累计收益差；同时给出上市以来和近5年年化跟踪差、年化跟踪误差，明确下图正值代表ETF领先。该图放在收益回撤章节内，不单独拆成产品分析长章。
4. **当前前十大盈利与分红：**横向双面板，左侧为利润同比、右侧为分红支付率，名称后标ETF净值权重；放在分红持续性表后。正负利润用不同颜色，支付率100%仅作参考线，不直接判定安全或危险。

视觉规范：白底、主图大、只开浅色横向或纵向网格；标题中性，结论留在正文；标签只标最新值、最大回撤和关键异常。生成后必须逐图目视检查，特别注意：

- 最后两个季度太近时，不要同时强行显示两个横轴标签；
- 右上角最新值、阶段名称与价格曲线不能重叠；
- 最大回撤标签放在图内，避免压住年份；
- 较宽的负利润柱将数值放柱内并用白字，避免标签与公司名称或持仓权重相撞；
- 图表必须紧跟对应正文和表格，禁止集中放在文章末尾。

### 6. 验证

- 从原始复权序列重算每个阶段起止价格、累计收益、CAGR、最大回撤及高低点日期；
- 从持仓CSV重算行业比例、前十大合计、代表股票权重和跨期名单重合数；若分析长期底仓，再核对进入前十大期数、最长连续期数、出现期间平均/最高净值权重及最新是否仍在前十；
- 从前十大财务表重算全部、主导行业及非主导行业的权重加权利润增长、ROE和支付率；
- 检查文章每个数字能回到归档文件，本地引用真实存在；
- 若原始价格文件的证券代码不符，停止使用并另取目标ETF数据，同时在资料说明中记录口径差异。
