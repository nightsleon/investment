# 官方指数资料核验工作流

用于只允许指数公司/交易所官网来源的指数研究，尤其是动态官网、编制方案 PDF、全收益代码和最新结构核验。

## 1. 先建立官方证据链

按以下优先级取证，并分别记录 URL、数据日期和原文：

1. 现行编制方案 PDF：选样空间、过滤、排序、样本数、加权、权重上限、调样和缓冲规则。
2. 指数详情页：名称/代码、简介、基日、基点、发布日期及编制概要。
3. 修订公告：核对现行方案何时生效、哪些条款被替换；不要把旧公告当成完整现行规则。
4. 官网动态接口：最新样本、权重、行业分布、行情及接口返回日期。
5. 数据服务说明或官方客服：解决公开页面无法证明的全收益代码、币种和税收口径。

最终输出要明确区分“PDF现行规则”“页面摘要”“修订公告”和“动态截面”，不能把它们揉成一句无来源的结论。

## 2. 动态官网取证

现代指数官网常由前端异步加载。页面初始快照为空时：

- 等待页面加载后重新读取正文；
- 切换“历史行情”“样本详情”等标签，再检查新增资源请求；
- 从浏览器资源列表识别官网自己的 JSON 接口；
- 直接打开该官方接口，记录返回中的日期、字段和值；
- 保存可复核的详情页 URL 和接口 URL，两者一起引用。

不要仅凭图表视觉估算权重。行业权重必须来自完整行业分布接口或官方文件；前十大必须来自带权重的样本接口，并注明截面日期。

## 3. PDF、彩页与链接有效性

- 同时给出官网查看页和实际 PDF 直链（若均可访问）。
- 必须实际打开验证；页面显示“彩页”按钮不等于后端存在有效文件。
- 后端返回空路径或直链 404 时，应写“当前未核实到有效官方单张”，不要构造惯例路径。
- 浏览器无法抽取 PDF 文本时，可用详情页摘要和修订公告交叉核验，但不能声称已逐字读取 PDF 中未取得的条款。

## 4. 全收益代码与历史下载

全收益是高风险口径，必须形成四项闭环：

1. 官方名称与官方代码；
2. Price/TR/NTR 类型；
3. 币种与股息税处理；
4. 官方历史下载入口或接口。

核验规则：

- 不按代码规律猜全收益代码；
- 不因历史行情可下载就把价格序列写成全收益序列；
- 官网检索不到只能表述为“公开页面未核实到”，不能断言指数不存在；
- 若任务强制全收益而公开证据不足，给出官方数据服务/联系方式，明确该项暂不可用于统一比较。

历史下载说明应写到可操作层级：入口页面 → 标签页 → 日期/频次 → 下载；若发现官方 API，可附参数化示例，但不要把未标注回报类型的 API 当成 TR 数据。

## 5. 规则链条写法

统一按：

`样本空间 → 可交易性/上市时间 → 分红资格 → 盈利质量过滤 → 排序选样 → 样本数 → 加权 → 单股/前N大/行业上限 → 调样与缓冲`

- “且”“或”要按原文逻辑保留，尤其注意联合剔除条件。
- 页面写“单股15%”而公告补充“前五大60%”时，应引用公告给出完整限制。
- 自由流通市值加权、股息率加权和分红金额加权不可混称。
- 调样频率与权重重设频率要分开；截面权重因价格漂移略超调样上限时，不应直接判定规则失效。

## 6. 最终核对

- [ ] 基日与发布日期分开，发布前历史标为回溯
- [ ] 样本目标数来自现行规则或详情页
- [ ] 每条关键规则有官方原文或清晰的摘要来源
- [ ] 修订公告的生效日已记录
- [ ] 单股、前N大和行业上限均核过
- [ ] 全收益代码/口径没有猜测
- [ ] 历史下载路径可操作且回报类型明确
- [ ] 行业与前十大注明同一或各自截面日期
- [ ] “未核实到”和“不存在”没有混用
- [ ] 所有链接实际打开验证过
