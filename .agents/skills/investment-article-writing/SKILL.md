# 投资分析文章写作

## 1. 触发与边界

用户要求把完整投资报告、3R投资简报和配套图表改写为公开文章时使用本 Skill。目标是有结构、有故事、简洁、通俗，同时保留投资判断深度。

不用于：

- 重新收集数据并生成完整投资报告；
- 独立3R盲评、评分和锁分；
- 只有公司名称、没有可靠研究底稿的即时荐股；
- 普通投资概念讨论。

用户说“仅讨论”“先讨论”时，只讨论结构和候选文字，不修改文章、Skill或参考文件；用户明确确认后，只改确认范围。

详细模板、篇幅、示例和校验见 `references/article-template-and-review.md`。

## 2. 输入与决策源

文章不是把研报删短。三类材料职责不同：

- 完整投资报告：证据仓库，提供业务、财务、治理、估值、数据表和图表；
- 最新锁定的3R简报：决策出口，默认提供评分、评级、行动、核心矛盾和证伪条件；
- 平台文章：围绕一个矛盾重新组织证据，让读者看懂为什么得出这个判断。

同时存在完整报告和3R简报时：

1. 评分、评级、行动和方向性结论以用户指定或最新锁定的3R简报为唯一来源；
2. 完整报告只补充数据、事实和图表；
3. 不混用旧总分、旧评级和旧行动；
4. 数据冲突先核对报告期、行情基准日和口径，不挑选更支持观点的数字；
5. 公开文章不写盲评、锁分、评估器数量、旧分差异和人工裁决过程。

## 3. 五个选股问题

文章按五个问题逐项验证：

### 3.1 能不能看得懂

关键不是业务客观上是否简单，而是投资者能否理解收入、利润、现金流、再投资和风险由什么驱动。公司的价值本质上是未来自由现金流的折现；看不清价值驱动因素，就没有可靠估值基础。分析最终落到每股价值，不能只看公司总利润增长。

### 3.2 能不能活得久

分三层判断：需求能否长期存在，行业利润池能否长期存在，公司能否持续参与并适应技术、渠道和监管变化。品类不易替代是加分项，但产品长期存在不代表原有公司一定能赚钱；优秀公司也可能主动适应产品替代。未来增长来源并入本节：行业总量、份额、产品结构、地域扩张和新业务，不再单设泛泛的“增长空间”。

### 3.3 利润能不能守得住

“月朗星稀”的集中格局通常有利，但既非必要条件，也非充分条件：分散行业可以出现强公司，寡头行业也可能因高固定成本和退出困难反复价格战。重点验证竞争者为什么难进入、客户为什么不愿切换，以及优势是否持续转化为份额、利润率、资本回报和现金流。

护城河与定价权必须分开。定价权不只等于直接涨价，还包括成本传导、少降价、产品升级、降本和不牺牲利润率的份额提升。监管、价格管制或强势客户可能限制绝对定价权；长期能力与短期价格压力也要分开写。

### 3.4 能不能高效复利

核心关系是“再投资空间 × 增量资本回报率 × 可持续时间”，并检查留存利润是否真正增加每股价值。轻资本通常有利，但不是高效复利的必要条件；高回报重资本公司仍可能创造价值，低回报高投入的增长则可能毁灭价值。

正文顺序为：资本开支与经营现金流/利润对比 → 当前ROE/ROIC与杜邦 → 增量资本回报、再投资空间与资本配置 → 自由现金流、负债和现金头寸。必须区分存量ROE与增量ROIC，也要把复利效率和下行安全分开；高ROE、低资本开支或现金充足都不能单独证明高效复利。

### 3.5 当前价格买得值不值

市场对增长、利润率、资本开支、资本回报、分红和风险的预期已经共同反映在股价中。增长陷阱的核心不是单纯比较利润增速，而是未来实际经营结果和每股价值增长能否好于买入价格隐含的整体预期。零增长公司若自由现金流收益率高且持续分红，也可能有好回报；高增长公司若现金流差、持续增发或估值收缩，也可能带来差回报。

前四问判断公司值不值得长期持有，第五问判断当前价格值不值得买。

## 4. 文章结构

固定为“开头 + 五问 + 行动”：

1. 结论型标题与数据范围；
2. 通用选股框架：五问看什么、为什么看；
3. 公司一句话判断：字母评级、3R分数、行动和五关答案；
4. 2—4个决定性数字与核心矛盾；
5. 一、能不能看得懂；
6. 二、能不能活得久；
7. 三、利润能不能守得住；
8. 四、能不能高效复利；
9. 五、当前价格买得值不值；
10. 六、五个问题的答案、3R表、行动与证伪条件；
11. 数据与口径说明。

标题直接写判断，不用“行业分析”“财务分析”等研报式标题。

## 5. 开头规则

开头的框架段与公司判断分开：

- 框架段回答“为什么看这五个问题”；
- 公司一句话回答“目标公司五关结果如何”。

公司一句话至少包含：

- 3R字母评级、总分和行动；
- 五关总体结果；
- 行业格局、业务持续性、护城河、广义定价权、资本强度、增量资本回报、再投资空间和自由现金流；
- 增长陷阱的方向性判断；
- 投资价值与仓位条件。

一句话可以长，但只能有一条主线。后面的决定性数字负责证明，不再重复整段框架。

### 3R字母评级

| 3R总分 | 字母评级 | 含义 |
|---:|---|---|
| 90—100 | A+ | 三个R均突出，重大短板很少 |
| 80—89.9 | A | 高质量投资候选，强烈关注 |
| 75—79.9 | B+ | 基本面较好，但有关键问题待验证 |
| 70—74.9 | B | 优点明确、短板明显，以观察为主 |
| 60—69.9 | C | 公司质量或价格存在明显不足 |
| 60以下 | D | 暂不值得投入研究精力 |

字母评级按总分机械映射；若3R门槛或重大红线要求降级，必须明确原因。

## 6. 增长陷阱与情景估值

第五部分只简短回扣增长陷阱，重点写它如何作用于目标公司：

- 市场按高增长、低增长还是衰退型资产定价；
- 实际经营为什么可能好于或差于这一预期；
- 回报来自利润增长、股息/回购还是估值变化；
- 股价与TTM利润经历了估值扩张、压缩还是利润下修。

情景估值必须让读者看懂：

```text
未来利润 = 当前利润 × (1 + 增长率)^年数
期末市值 = 未来利润 × 期末PE
价格回报 = 期末市值 ÷ 当前市值 - 1
累计总回报 ≈ 价格回报 + 静态股息率 × 年数
```

优先用表格展示：情景、未来利润公式、期末PE、期末市值、价格回报、累计静态分红和累计总回报。

必须说明：

- 完整价值来自未来自由现金流，利润×PE只是便于理解的简化情景；
- 静态分红未考虑未来分红变化、税费和再投资；
- 使用利润×PE时不再机械加回全部现金，避免现金价值重复计算；
- 情景用于比较赔率，不是精确预测。

## 7. 图表与篇幅

默认使用3—5张核心图：

1. 利润趋势与增速；
2. ROE与杜邦三因子；
3. 净利润、经营现金流和自由现金流；
4. 股价与TTM利润。

每张图紧跟支撑它的正文。产品结构、现金头寸、营运质量只有在改变主线判断时才加图。

正文通常2500—3900个汉字。加入完整五问框架时可适度超过3600字，但不能变成5000字以上的压缩研报；增加框架后同步删掉开头、第五部分和结尾的重复判断。

## 8. 写作与去AI味

- 保留明确的第一人称判断，不写两面都对的空话；
- 用具体数字和关系代替“重要、显著、值得期待”等泛词；
- 少用“这意味着、总体来看、核心在于”式套话；
- 不宣布“下面开始分析”“计算逻辑并不复杂”，直接进入内容；
- 不堆加粗、emoji、规则三段论和整齐口号；
- 小标题写公司结论，正文长短句交替；
- 事实、推断和观点分开，无法确认的事项明确写“待验证”；
- 结尾直接给行动和证伪条件，不写“一句话收尾”“未来可期”。

最后加载 `humanizer` 做发布前检查，但不得为了口语化牺牲专业口径。

## 9. 数据与参考说明

文末只保留读者需要的信息：

- 参考材料和可访问链接；
- 行情、财务和年度数据截止时间；
- 影响结论的未验证事项；
- 估算值与确认值的边界。

使用“本文参考[《文章名》](URL)”，不写“改写自”。

### 9.1 文件命名后缀约定
若从现有完整投资报告或研报底稿改写为公开文章，生成的文件名必须添加平台或版本后缀（例如 `{原报告名}_雪球知乎版.md`），严禁直接覆盖原研究底稿。

### 9.2 文末固定合规后缀（写进文件里，留在对话外）
在将文章写入最终 Markdown 文件时，文章文件正文最末尾必须统一附带标准的互动引导与合规风险提示；**绝对严禁在日常聊天对话回复末尾输出此文案**：

```markdown
---

如果您觉得这篇文章有启发，欢迎点赞、转发、关注！

风险提示： 本文仅供参考，不构成投资建议。市场有风险，入市需谨慎。
```

## 10. 执行与验证

1. 读取3R简报、完整报告、图表和现有文章；
2. 锁定评分、评级和行动的唯一来源；
3. 写故事卡：五问答案、核心矛盾、预期差、行动和证伪条件；
4. 按“五问 + 行动”重组，不按原报告章节删减；
5. 写初稿并放入决定性图表；
6. 去AI味、删除重复观点；
7. 做矛盾审计和机械校验。

完成前确认：

- 五个问题的用词全文一致；
- “投资价值已出现”与“重仓条件未满足”不冲突；
- 长期护城河/定价权与短期压力分开；
- 历史高增长没有直接外推；
- 估算现金与确认现金没有混用；
- FCF低于分红时写“接近覆盖”，不写“完全覆盖”；
- 情景估值可重算，3R分项之和等于总分；
- 行情统一称“报告基准日”而非实时价格；
- 图片和参考链接有效；
- 文末已附上标准互动与风险提示（如果您觉得这篇文章有启发，欢迎点赞、转发、关注！ / 风险提示：本文仅供参考，不构成投资建议。市场有风险，入市需谨慎。）；
- Markdown通过 `git diff --check`；
- 只修改用户指定范围。
