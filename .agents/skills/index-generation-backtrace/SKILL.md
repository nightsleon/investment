# 指数世代回溯报告（基日分代视角）

独立于评分榜主报告的另一视角：按**指数基日**（不是发布日）分代，回溯各组基日至今的全收益表现。用户已确认的报告边界与口径（2026-08，红利指数项目）：

## 报告边界（用户明确要求）
- **只做回溯描述**：不做评价排名（总收益倒序仅为排列顺序）、不做未来预判、不做跨组比较判断
- **分组按基日**：如红利指数30只池 -> 2013前世代 / 港股通世代(2014-11-14) / 央企定制世代(2016-12-30)
- **组内统一起点（用户修正，重要）**：每组从该组最晚基日起算（如2013前组统一从2013-12-31），终点统一到最近交易日。组内窗口完全一致后总收益才可直接比较；否则基日不同（如2004 vs 2013）比较总收益/CAGR起点效应不公平。报告名不能叫"基日至今"，叫"统一起点"
- **组内表格列序（用户修正）**：主指标在前，辅助信息靠右：指数/代码 -> 总收益 -> 全程CAGR -> 近3年CAGR -> 全程波动 -> 近3年波动 -> 最大回撤 -> 收益波动比 -> 年度胜率 -> 滚3中位 -> 基日 -> 回溯
- **CAGR命名与波动配对（用户修正）**："全程CAGR"配"全程波动"、"近3年CAGR"配"近3年波动"，命名必须成对统一，不裸写"CAGR"
- 波动率两列：全程（组内统一起点至今）+ 近3年（近3年窗口单独算）；收益同样加近3年CAGR列，可发现长短期背离（如香港红利全程12.6%→近3年23.5%；消费红利全程12.7%→近3年-8.3%）。近3年不用近5年（与全程窗口重叠度高、信息增量小）。典型发现：多数指数近3年波动低于全程（风格趋稳），含港股大波动的反向
- 报告开头放"怎么看懂这张表"通俗指标说明：每个指标一句人话（总收益=1万变多少、滚3中位=随机挑月买入拿3年典型年化等）
- 报告结构：指标通俗说明 -> 口径说明 -> 世代划分由来 -> 各世代一章（表+组内图景）-> 跨世代图景表（只描述）-> 附录（数据来源归档）

## 口径
- **波动率：日频年化** = 日收益率std(ddof=1)×√242，与中证官网指数快照口径一致，读者可用官网验证。若同项目另有月频口径报告，须注明两套口径不可直接比较
- **滚动3年中位数怎么算**：月频收盘 -> 每个月末算往前36个月的年化收益（(月末/36月前)^(1/3)-1）-> 得到滚动序列 -> 取中位数。含义"随机挑月买入持有3年的典型年化"
- 回溯占比 = (发布日-统一起点)/(终点-统一起点)，注意统一起点晚于部分指数基日时按新起点算
- **回溯口径双定义事故（真实事故）**：报告里曾同时存在两套回溯定义——基日口径(发布日-基日)/(基日→今)与窗口口径(发布日-组内统一起点)/(窗口→今)。从"基日至今"改版为"统一起点"后表格数字沿用旧口径，导致"表格里大都是回溯"与"统计中位数0%"直接矛盾（2013前组8只发布日早于窗口起点2013-12-31，整段窗口均为实盘→回溯0%，中位数0%；基日口径中位数39%）。教训：①改版方法论时必须全量切换表格数字，统计脚本与表格口径必须一致；②口径节要写明定义与例子（如"8只发布日早于窗口起点，回溯0%"）；③切完口径后复查组内图景里引用回溯的表述（如"实盘最足"在8只0%下产生歧义，改"发布最早、实盘验证最久"）

## 关键技术点
- **数据重采**：本地归档Excel（downloadindex-perf导出）通常只含近10年；基日至今回溯必须用中证官网接口重采：
  `https://www.csindex.com.cn/csindex-home/perf/index-perf?indexCode=<TR代码>&startDate=<基日YYYYMMDD>&endDate=<结束YYYYMMDD>`
  返回data数组含tradeDate/close，基日起1000点（部分为3000点）
- 基日/发布日来自 basic_info.json（index-basic-info 接口归档）
- 采集脚本与指标脚本分开放 `scripts/generation/`，原始CSV+manifest归档 `sources/performance-data-30index/generation-full-history/`
- 抽样复算验证：独立重算1-2只的总收益/CAGR/波动与表内一致后再出报告

## 表格编辑坑（真实事故）
- **用脚本批量改Markdown表格列时极易错位/丢表头**：本会话插入"近3年CAGR"列时脚本插了重复列（CAGR值出现两次、后续列整体右移），后续修复脚本又把表头行整个删掉导致表格无法渲染。教训：
  1. 改列优先手工patch精确行，不要正则批量重排
  2. 改完必须校验：每张表 表头列数 == 分隔行列数 == 每数据行列数（一行python即可），并grep确认表头行仍在
  3. 用户报告"表格无法渲染/错位"时，第一怀疑：表头行丢失或列数不齐

## 深挖章节（用户认可的方向，按信息量排序）
回溯描述主体之后可加"深挖"章节（全部基于实算数据，中间结果存CSV归档）：
1. **回测光环定量检验**：①回溯占比与全程CAGR的相关系数（2013前组0.81）；②每只"全窗口CAGR - 仅发布日后实盘CAGR"差值表。注意反例解读：差值混杂"发布日赶在市场高位"的时代效应（这批指数多发布于2008-2009高点），非纯回测偏差；发布于底部区域的（国新2022年底）实盘反高于全窗口
2. **长短期四象限**：以各组内全程CAGR中位/近3年CAGR中位为界分四类（动量延续/衰减/估值修复/双弱）。典型发现：背离方向由市场暴露决定（A股质量红利衰减、港股红利修复），非世代本身
3. **波动时间结构与港股效应**：波动比=近3年÷全程，全样本中位0.84；变颠(>1)的集中在含港股；按纯A股/含港股分组对比表——"红利低波化是A股现象"是强结论
4. **总收益排序与RV排序错位**：列错位事实即可，不构成选择建议（守住"不评价"边界）
5. **滚3中位样本量caveat**：滚动窗口数随世代递减（180+/100/80个），新指数滚3几乎由近年行情决定

## 样本过滤坑（真实事故）
- **剔除名单必须程序化全量筛选，不抄旧报告人工标注**：本会话从主报告F表手摘"规模偏小"剔除名单，漏了LOF类小基金（930917 SHS高股息唯一跟踪产品501307仅0.65亿LOF，规则ETF≥2亿/场外≥5亿/LOF兜底，本应剔除），报告发完才被用户指出。正确做法：从`sources/track-funds/_汇总_跟踪基金统计.json`按规则代码化筛选每只指数的全部跟踪产品（含LOF/场外），生成剔除名单并在报告口径节声明筛选逻辑
- 若剔除导致某组样本过小（如港股通世代5->4只），仍坚持规则一致性优先于样本数量，并在报告注明

## 基准对比图（用户认可的产出形态）
- **大组（10+只）用分类合并图（用户最终形态，2026-08确认）**：正文不再逐指嵌图，按叙述分类（稳定跑赢/高超额依赖时段/与基准打平/稳定跑输）各画1张合并图嵌入正文，图与文字分组1:1对应；每类图=该类指数+基准灰虚线，图例基准置顶、其余按累计收益降序，标题带类名，起点=组内统一起点，**figsize=(13,6)横宽纵扁**（用户纠正10×7.5"横轴短纵轴长比例失调；时间序列长图横向舒展）。单指逐指对比图（每只vs基准一张：红线=该指数、灰虚线=基准、线尾标注区间收益）仍生成但**归档 `01_主报告/世代对比图/` 不嵌入正文**，附录注明"已归档"
- **小组（≤5只）用组合对比图**：全部指数+基准画一张图（如港股通4只、央企定制3只 vs 全局基准红利低波）。规范：基准灰色虚线**置顶**（最后画、图例第一项，不参与排序）、其余按累计收益降序排图例、每条线标注简称+区间收益、标题注明"vs 全局基准（红利低波）"、起点=该组统一起点。文档配"### 世代 vs 全局基准"小节：图 + 逐指对比（基准先写：同期总收益/CAGR/在含基准的N条线中排第几/跑赢几只） + 小结
- **章节位置（用户修正）**：基准对比小节一律内嵌在对应世代章节内部（组内图景之后，### 级别），三组结构对称；不要做成独立大章节放在深挖章节之后（曾把2013前组对比做成"## 十"挂在深挖后，用户要求并入第一节）
- 每图配一句简洁对比总结，按"超额收益+年度胜负（该指数年度收益>基准的年数/总年数）+回撤差"三要素分类型叙述（稳定跑赢/高超额依赖个别时段/与基准打平/稳定跑输）
- 读图小结锚定基准在组内的位置（第几名、跑赢跑输只数、跑赢者是否靠集中时段行情）

## 基准指数推荐：分析基准与投资标的必须分离（用户挑战后确立）
推荐世代基准指数时分两层说：
- **分析基准**（衡量该世代典型长相的锚点）：只看指数本身数据质量（回溯占比低、实盘落差小）+ 收益风险比 + 画像接近组内重心。例：东证红利低波（RV组内第一、实盘落差仅1.9pp）
- **投资标的**：必须核查跟踪产品生态——数量、规模、跟踪误差/跟踪差。东证红利低波仅1只场外基金（012708，65亿），年化TE 1.78%看似合格但**累计跟踪差-10.65%**（4.5年），复利下严重拖累
- 一句话结论范式："分析用X，投资别选X"——世代内最优指数和最优可投资标的常不是同一只，这个割裂本身值得写进报告
- TE与跟踪差要分开看：TE小≠跟踪差小；场外指数基金的费用+现金拖累主要吃在跟踪差上

## 高回测指数的编制规则质量评估（2026-08会话新增）
用户会追问"回测占比高的指数到底是规则优秀还是过拟合/反身性导致的漂亮数字"。评估方法：
- **必须读编制方案原文**，不凭指数名猜测。PDF已归档 `sources/index-methodologies/<代码>_<简称>_编制方案.pdf`，用pypdf逐页提取全文即可
- **三因子判定框架**：①规则本身有无独立经济逻辑（每道工序能否讲出"为什么该有效"）；②过拟合痕迹--筛选链工序数与阈值精修程度（讲不出理由的精修阈值=测试出来的），以及**公式套壳证据**（同一链路被多个新指数逐字复用，如中证红利质量932315的"12季度ROE标准差前80%+股息率前50%"被A500红利低波932422复用）；③反身性--发布时点是否踩在策略拥挤/产品线大干快上期
- **母指数后视镜偏差**：母指数自身晚发布（A500自己2024年9月发布）却号称2013年起业绩=用今天的成分名单回套，幸存者偏差嵌在母池里，这类指数回测数字参考价值最低
- **前瞻性选样是真创新的信号**：用当年分红预案股息率（前瞻）而非过去三年股息率（滞后）选样、调仓时点紧接年报披露完毕，是有独立逻辑的设计（智选高股息932305）
- 结论可给梯度排序（规则加分 vs 回测减分），正文明细压缩到每只2-3句，六道工序全文移附录

## 标题打磨（2026-08会话讨论）
用户嫌"全景回测：22只指数拉到同一起跑线后，我理出了一份选基参考"不够硬核。候选方向：A数字冲击型（"22只红利指数12年大横评：榜首588%，但83%是回算的"）、B打假/悬念型（"收益前五的红利指数，四个没经过实盘检验"）、C反差故事型。用户偏好A类：数量+年限+收益+水分四个信息同框，"588%"与"回算"同框的反差正是全文核心发现；B类"猫腻"式标题与正文克制的结论（回测光环存在但被时代效应放大）不匹配，避免标题党。讨论确定方向后再改标题及文中呼应处，仅讨论时不动文件。

## 写作要点
- 组内同基日（如港股通世代5只同时长）是纯策略对比，可强调；跨时长组的总收益受复利时长影响需提示
- 世代扎堆背景可解释：港股通系基日=沪港通开通前最后交易日（样本池硬约束）；央企定制系=年末统一基期+发布前2年回测
- 跨世代"收益/波动/回撤递减"类图景必须归因于起点与时长不同，不下策略优劣结论
- 用户问"推荐哪只做基准"时先答分析层，再主动交代投资层（产品数量/规模/TE/跟踪差），不要等用户用"可是跟踪产品差"来纠正——本会话即因此被纠正

## 写作数字引用坑（本会话被用户连续抓错两次）
- **排名表述必须实算后写**：写"基准在组内排第几"前先按总收益排序数清楚（含基准的N条线排第几、跑赢/跑输几只），写"在组内排第二"实际是5条线中第三会直接被抓
- **引用表外数字必须当场计算**：正文引用表格没有的数字（如基准的MDD、基准CAGR）先跑一行python实算再写；本会话凭印象写基准回撤-33.4%，实算-27.53%（起点不同值不同），又被抓一次
- **年度胜负统计排除不完整年度**：计算"年度胜基准"用完整年度（起算次年至末年前一年，如2016末起点→2017至2025共9年），脚本里resample("YE").pct_change()会把起点年末和当前不完整年（2026）算进去导致虚高（5/10 vs 4/9）；要么脚本过滤要么正文注明
- 修正被指出的数字后，顺带复查同段文字里其他未实算的数字（同一条bullet常有多处引用）
- **\"超额集中年份/因子大年\"表述必须逐年实算（本会话被抓第三次）**：写\"超额集中在2017、2025质量因子大年\"前必须逐年算（指数年度收益-基准年度收益）；中证红利质量实际大额超额年是2017(+28.0pp)、**2020(+34.7pp，最大)**、2019(+16.5pp)、2025(+14.8pp)，红利质量是2015/2017/2019/2020四年——凭印象漏掉最大年会被抓。用户常基于图面斜率质疑（\"2020、2021涨幅很大\"），应对两步：①逐年超额实算摆出年份表；②**区分绝对涨幅与相对超额**——2020暴涨(+37~43%)属实，但2021绝对收益仅+9~10%且跑输基准(+16.3%)，图上陡峭斜率是2019+2020叠加的视觉错觉。回应模板：\"你看到的是X，实际逐年超额是...，其中N年绝对涨幅大但超额为负\"
- 顺带统一\"胜X年\"口径：全部改\"胜基准X/完整年度数\"（如胜基准6/12），不要混用含不完整年的13窗口数（7/13）

## 口径/样本切换后的全量复核清单（用户会主动问"还有哪里要改吗"）
方法论或样本一变（统一起点改版、剔除指数、回溯口径切换），按此清单全量复查，避免只改表格漏改正文：
1. 概述/样本数/口径节（"23只"→"22只"、剔除名单追加）
2. 世代划分由来、分组章节标题（5只→4只）
3. 主表格：删行/改列，表头-分隔行-数据行列数一致
4. **组内图景**：引用旧数字的表述（回溯占比范围、分档、实盘年数）；口径切换后检查"实盘最足"类歧义表述
5. 跨世代汇总表：组中位数全部重算（含回溯中位——之前手写过~55%实际两口径分别是39%/0%）
6. 深挖章节：相关/分组/四象限/市场分组的数字重算，中间数据CSV同步重生成
7. 附录：脚本名、文件清单
8. 每处替换用grep确认无残留旧值

## 报告改写为雪球等平台发布文章（用户明确要求的固定风格）
回溯报告是分析底稿，平台文章是独立产出（新文件，不改原报告）。用户确认的结构与风格，每次写财经发布文章都用：
- **结构**：主线矛盾贯穿全文 -> 钩子(反差数字+悬念，如"588% vs 118%，但榜单本身不公平") -> 方法一句话带过(详细口径移文末) -> 分节每节一个故事(每世代/每分类只留一个最有代表性的发现，不逐项复述) -> 跨节规律(压缩成一小节，四象限为主、港股效应一句带过) -> 实操建议(按需求对号入座+避坑清单，收在可操作的问题上) -> 附录(口径说明+22只全量数据表当收藏点)
- **风格**：深入浅出、简洁通俗、有故事性、去AI味（不堆加粗/套话/三段论口号）；术语首次出现用类比一句话讲透（如回测占比="用考试原题练出来的学生考同一张卷子"）；标题直接写判断带悬念；**不锁字数与固定结构模板**（用户明确纠正："有的文章长有的短"，只约束表达风格本身）；不逐条罗列口径说明，融入正文首现处
- **与报告的差异**：报告"只描述不判断"，文章可适度给有证据支撑的观点（回测光环、指数≠基金），但不做具体推荐；附录的脚本路径换成一两句可复现说明；指标通俗说明整节砍掉
- 案例：`上证官网红利指数大比拼/01_主报告/三代红利的比赛_雪球发布版.md`（配图：3张新生成图存 `01_主报告/雪球配图/`、脚本 `scripts/generation/gen_xueqiu_charts.py`；图表脚本可从指标JSON+原始CSV直接生成散点/四象限/条形图；注意雪球不支持markdown本地图片路径，发布时手动上传）
- **表格严格按声明的规则**：用户问"某只为何没入选"时先复算口径回答；除非用户确认，不主动往规则筛选出的表里补行（中证红利质量差值+1.6pp排不进前五，用户明确"按规则他确实不在前5，不用补充"）
- **正文与附录的体量平衡**：讨论中不断往正文加料会把建议类小节膨胀成嵌在文中的小论文，与其他小节（每类3-4行）颗粒度失衡。用户认可的做法：正文压缩到结论+最有记忆点的表达（"后视镜选池""公式套壳"），工序明细/论证材料移文末附录小节，正文加一句"明细见附录"指引；重复展开的内容（如回测为何打折）指向已有量化章节（第五节实盘年化对照）不重讲
- **指数指代必须精确**：中证红利质量（932315）与红利质量（931468）是两只不同指数，同类还有多对"中证X"与"X"；引用实盘年化/回测数据时先核对代码，张冠李戴会被用户当场抓住（本会话真实事故：把红利质量的实盘年化7.99%安到中证红利质量头上）
- **用户review抓错四连（2026-08，雪球发布版会话）**，都是"正文/表格不自洽"类，成稿后按此自查：①正文结论用了表内没有的指标（波动比0.78/1.00，表里只有全程波动一列）->补原始数据列或加"明细见附录"；②"查基日与发布日距离"口径错->改"统计起点与发布日"并说明基日无信息量；③推荐段只写优点不写跟踪差（SHS红利成长LV）->与东证案例对称补可投资性代价，数字从归档JSON实取（007751累计跑输19.21pp、TE 1.98%）；④"LOF和指数增强慎碰"不写原因->各补一句括号注释
- **加列要全表覆盖，不只改被点名的表**：同一方法论列（近3年波动）在多张世代表都存在时，用户指出一张表缺列，其余表也要同步补齐，保持三张表列结构完全一致；数字从归档指标JSON按指数名批量取出，不手抄

## 基金表现 = 指数规则 + 跟踪质量，分账方法（2026-08会话新增）
用户用雪球对比基金后问"指数规则是否真有优势"，正确答法是拆账，不直接认同基金表面胜负：
- **同区间三层对照**：基金分红再投净值（fund-nav-correct归档，含reinvested_nav列）vs 指数全收益（generation-full-history归档CSV）vs 基准指数；每个共同起点分别算总收益/CAGR
- **分账公式**：指数超额（该指数全收益-基准全收益）- 跟踪损耗（指数全收益-基金再投净值）= 基金净超额。典型结论形态：规则超额+16.7pp、跟踪损耗-13.1pp、净剩+3.6pp--"指数的优势是真的，但它是指数的不是你的"
- **"成立以来"对比是陷阱**：不同成立日的基金直接比总收益=比"谁的生日更走运"（512890成立2018年末吃到2019-2021红利大涨，007751成立2019-09起点更晚），必须拉齐共同起点截取再比；拉齐后起点落在风格启动前与否还会翻转结论（近3年景顺长城赢、2019年起华泰柏瑞赢），要点破窗口运气
- **跟踪损耗量级参考**：ETF约5pp/全程，场外指数基金5-15pp（费用+现金拖累），经常比指数间规则差异还大--强化"先查跟踪产品再谈指数好坏"
- 结论三段式：规则优势存在（指数层）->规则优势≠到手优势（基金层打折）->窗口要小心（起点效应）

## 报告一致性审查（成稿后review，用户认可清单）
用户会请agent通读全文查"逻辑前后是否一致/语义不通顺"。审查要点（按命中率排序）：
1. **派生指标的窗口口径混用（真实事故）**："全窗口CAGR - 实盘CAGR"差值表曾把实盘CAGR从发布日（2008年）起算、全程从组起点（2013年）起算，两个不同长度窗口直接相减，把发布日早于组起点、实为纯实盘的指数（中证红利）列出差值+5.9pp。正确口径：实盘起点=max(组起点, 发布日)；发布日≤组起点则差值为0不入表。修法：写一行python独立复算差值表全量（顺带得差值中位数），替换错行
2. **正文引用的样本量与表格口径打架**：表格胜率/11（11个完整年度）但基准对比正文写"12个完整年度、7/12"——同组完整年度数全文统一，grep所有"/12""/N"确认
3. **滚动窗口数声称与实际口径不符**：正文写"约180+个窗口"对应从各指数自身基日起算，但脚本（calc内先截断到组起点再滚3）实际是统一起点口径117个。**核验方法：读计算脚本确认截断发生在滚3之前**，再实算窗口数替换文字；数据不动
4. **口径节表述引发误读**："起点即基日，两口径一致"易被读成回溯0%，但港股通/央企定制组发布日晚于基日1-4年仍有回测段。补"起点即基日≠发布即起点，先定基日回算后发布"
5. **分类规则与个体归类冲突时尊重用户判断**：四象限按组中位分界，上国红利全程CAGR(11.68%)略低于组中位(12.65%)，机械按规则应属"长弱短强"，但用户认为"两值都不低，归长强短也强没毛病"——保留归类，补一句贴线说明（略低于中位但接近，按近3年强弱归类）。边界样本归类可加注不硬挪
6. **"反向/例外"计数两处不一致**：第一节说"仅两只反向"（把波动降幅最小的也算进去），第四节例外只列港股系3只。反向=近3年波动>全程波动，降幅小≠反向；两处统一
7. 抽查数字用归档指标JSON（如generation-full-history/世代回溯统一基日指标.json）逐项对表，总收益/CAGR/胜率/回溯占比全对后再审文字
