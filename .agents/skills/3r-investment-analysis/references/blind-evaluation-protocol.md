# 3R盲评与受限证据协议

适用于用户要求“盲评、仅限指定证据包、不得查看原报告/旧评分/网络”的任务。

## 1. 证据隔离

1. 先记录允许访问的文件名或路径白名单。
2. 只发现白名单目标；不要读取同目录README、旧3R、原报告、图表、脚本输出或联网补缺。
3. 评分框架属于方法说明，不属于公司事实来源；公司事实只能来自允许的证据包。
4. 缺失数据写“待验证”并扣分，不得用常识、同行数据或原报告印象补齐。
5. 最终披露证据边界，并明确是否访问过白名单外资料。

### 1.1 从原报告制作事实包

允许保留财务、业务、治理、估值数据、计算口径和图表；必须删除原报告的模块分、总分、评级、方向性总结、胜率赔率、毛估估情景、投资结论和行动建议。原报告的压力/中性/乐观假设属于评价，不属于原始数据，Right Price情景应由盲评员重新建立。

优先使用：

```bash
python scripts/build_blind_evidence.py 原报告.md /tmp/公司_事实包.md --company 公司名
```

脚本通过后仍需人工搜索污染词，并抽查被删除的是完整Markdown区块，而不只是标题。最危险的失败模式是删掉“毛估估”或“评分”标题，却残留其情景表和分数表；区块跳过状态必须在每一行生效，直到同级或更高级标题才恢复。只要发现旧情景或旧评价残留，该轮评估结果全部作废，修复事实包后重新盲评。

即使脚本返回PASS，也必须额外做一次“方向性污染审计”，至少搜索并处理：`先说结论`、`初筛结论`、`投资价值`、`主要风险`、`好行业：`、`好公司·定性：`、`好公司·定量：`、`好时机：`、`强烈关注`、`不碰`。处理原则：

- 含总评、投资价值或行动倾向的整句删除；
- 仅标题带方向性、正文仍是事实的，改写成中性标题（如“业务模式概述”“行业需求与竞争格局”“财务与经营数据”“估值与股东回报数据”）；
- 风险事实、原始财务数据和可核验经营事实保留，但删除“便宜、优秀、值得”等结论性修饰；
- 审计应以零命中或逐项人工确认结束，不能把脚本PASS当作脱敏完成。

若当前评估器已经看过旧分，不能靠“主观忽略”消除锚定，必须更换隔离上下文评估器。

## 2. 固定28项

- Right Business：21项（4+4+4+5+4），合计60分。
- Right People：3项，合计20分。
- Right Price：4项，合计20分。
- 总计28项、100分，最小0.5分。

建议使用稳定ID：`B1-B21`、`P1-P3`、`V1-V4`。每项都必须同时包含：名称、满分、得分、证据与判断。大维度必须由其子项相加，不得先定大分再倒推子项。

## 3. 四组易混概念

- **护城河 vs 定价权**：认证、渠道、品牌、转换成本可证明难替代；提价、单位收入、量价、成本传导和毛利率才证明定价权。护城河高不自动带来定价权高。
- **ROE vs 轻资本**：ROE计入回报率；资本开支、在建工程、产能利用率计入资本强度。高ROE不能替代轻资本证据。
- **CFO vs FCF**：CFO检验经营回款；FCF必须扣资本开支。CFO覆盖利润不代表扩产后仍有充足股东现金。
- **历史增长 vs 最新趋势**：3年/5年兑现、稳定性和来源质量分别计分；最新年度、季度或TTM单列，不能用高历史CAGR掩盖当前下滑。

同一事实原则上只归入一个主要子项；若跨项引用，必须说明它在不同项目中验证的是不同命题。

## 4. 门槛和评级

先算三模块，再算总分：

- Business <36：不得因低估值给买入级结论；
- People <12：不得作为核心持仓；
- Price <10：结论必须等待价格；
- 重大治理、财务红线或商业模式不可理解：直接降级。

机械评级：≥85重点候选，75—84关注，65—74观察，<65不碰。最终评级必须同时服从机械评级、三门槛与重大红线。

## 5. JSON与程序化校验

当用户要求完整JSON时，JSON至少包含：方法元数据、每家公司28项、五个Business维度小计、三个模块分、总分、门槛布尔值、重大红线和最终评级。正文与JSON必须完全一致。

交付前运行 `scripts/verify_3r_json.py <report.md-or-json>`，验证：

- JSON可解析；
- 每家公司恰好28项；
- ID完整且顺序为B1-B21/P1-P3/V1-V4；
- 每项为0.5分粒度且不超过满分；
- 维度、模块、总分逐级相等；
- 门槛布尔值与分数一致；
- 最终评级不高于门槛和红线允许的结果。

若校验失败，修正最底层子项或错误小计，禁止只改总分掩盖不一致。

## 6. 多评估器汇总与简报回写

重要批量任务使用至少3名隔离上下文评估器。这里的“3名”是3份**有效、已落盘且通过校验**的完整28项JSON，不是3段聊天摘要：

- 评估器声称完成但JSON未创建、无法解析或校验失败，该评估器整组结果无效；
- 只有总分摘要而没有28项JSON，不能参与中位数；
- 不得把有效评估器数量从3降为2，也不得用两人平均代替；
- 必须派新的隔离评估器从零补位，且禁止其读取已有评估器结果；
- 补位完成后，先分别运行`verify_3r_json.py`，确认3份工件都有效，再汇总。

正确汇总方式是：

1. 对B1-B21、P1-P3、V1-V4共28项分别取中位数；
2. 用逐项中位数重新加总五个Business维度、三个模块和总分；
3. 不直接平均总分，也不直接取总分中位数；
4. 指标极差≥1.5分时复核；指标满分不足3分且极差≥1分时也复核；
5. 复核只看事实证据和各评估器独立情景，不看原报告或旧3R分数；
6. 逐项中位数形成初始锁分，完成第7节系统性偏差复核并形成最终锁分后，才允许查看旧分并解释差异；禁止为了接近旧分回调。

重写简报时必须同步替换28项、小计、模块、总分、评级及Right Price情景；不得保留原报告毛估估。数据边界应披露事实包范围、评估器数量、逐项中位数方法和锁定时点。加入README时只更新3R评分与3R链接，完整报告字段保持不变。

最终除JSON校验外，还要验证：简报28项与中位数或经记录的人工裁决结果逐项一致；固定四图（ROE/杜邦、利润趋势、现金流与利润、股价与利润线）恰好齐全；每张图紧跟对应分析段落、不连续堆叠；图片与完整报告共用同一`charts/`路径且链接存在；README两类链接存在；原完整报告日期/分数/评级/链接未被覆盖。

## 7. 中位数后的系统性偏差复核

逐项中位数是初始盲评结果，不是最终裁决。多名评估器可能因使用相同事实包和指标，出现相同的框架性偏差；即使评分高度一致，也必须完成以下检查：

1. **证据重复计分**：同一事实是否在两个以上指标中重复加分或扣分；跨项引用时必须说明分别验证什么不同命题；
2. **长期与短期错位**：3年/5年增长和年度稳定性评价长期兑现，最新季度/年度/TTM单列；单季度波动不能同时否定多年稳定性；
3. **行业风险机械叠加**：长期需求、周期性、品类替代、长期空间和定价权分别验证，不能用同一组风险跨项重复扣分；
4. **商业模式优势重复奖励**：高毛利、轻资本、ROE、现金流、品牌和定价权各归入对应指标，不能因整体印象在多个维度重复加分；
5. **证据折扣与质量判断混淆**：缺少市场份额、治理细节或ROIC数据时可保守扣分，但必须标注为“证据不足”，不能写成公司能力不成立。

发现上述问题时，允许在查看旧分前进行人工裁决。调整必须：

- 落到具体B/P/V子项；
- 记录原分、新分、事实依据和防重复理由；
- 重新加总维度、模块、总分与评级；
- 不以接近原报告或旧3R为目标；
- 在简报数据边界披露初始中位数和人工调整。

锁分分两层：逐项中位数形成“初始锁分”，系统性偏差复核后形成“最终锁分”。只有最终锁分完成后，才允许查看旧分并解释差异。

## 8. 存量3R简报批量回补

用户要求“其余已有3R也全部盲评/补图”时，按存量集合处理，不逐份临时发挥：

1. 枚举仓库全部`*_3R投资分析简报_*.md`，列出已合规与待回补公司；
2. 对待回补公司逐一确认完整报告、README行及固定四图现状；已有四图只复用，不重复生成；
3. 为所有待回补公司制作同版本脱敏事实包，并执行污染词、旧分格式和完整区块抽查；
4. 同一批次使用3名有效隔离评估器覆盖全部公司，逐项中位数后再交给未看旧分的隔离裁决员做系统性复核；
5. 最终锁分后再让报告编辑器读取旧3R并回写28项、模块、评级、独立V4情景和盲评披露；报告编辑阶段允许看旧稿，但不得改最终分数；
6. 统一更新README的3R评分/链接，不动完整报告字段和原排序；
7. 对仓库全部现有3R简报运行`scripts/audit_3r_library.py <repo-root>`，而不只验证本批次文件。

若父会话已见旧分，父会话可以做机械汇总和最终验证，但系统性偏差裁决必须交给只看事实包与中位数文件的隔离评估器。
